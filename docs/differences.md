# Where E8 differs from Emacs

E8 behaves as Emacs does, and the oracle in `tests/emacs/` checks it on recorded cases. This page lists where it does not: behaviour E8 has that works differently, either on purpose or because matching Emacs is not done yet. It is the place to look before reporting a difference, and the place to add one when it is found.

It does not list what E8 lacks altogether. That is in [plan.md](plan.md) (the gaps in the core) and in each ADR's consequences. Ideas for doing better than Emacs on purpose, later, are in [departures.md](departures.md). Cases the oracle knows differ are in [`tests/emacs/known-gaps.txt`](../tests/emacs/known-gaps.txt).

Each entry says whether the difference is **deliberate**, which keeps it, or **not yet** fixed.

## How code runs

- **Waiting for input** (deliberate): Emacs's Lisp waits inside `read-key`, `yes-or-no-p`, `read-from-minibuffer` and `recursive-edit` until the answer comes. E8's commands return, and the answer runs code given with the request, which scripts write as `await` ([ADR 0030](adr/0030-the-command-loops-primitives.md)). What the user sees is the same; code after the question runs later rather than in the same call.
- **Keys and events** (deliberate, for now): events are key descriptions, `"C-x"` or `"<mouse-1>"`, not Lisp values carrying their positions. A mouse event's place is the last mouse event's, from `lastMouseEvent` ([ADR 0030](adr/0030-the-command-loops-primitives.md)).
- **Strings** (deliberate): JavaScript strings have no unibyte form. So `downcase` of an ASCII-only string follows a buffer's own case table, where Emacs's ignores it ([ADR 0032](adr/0032-character-tables.md)).
- **Positions in scripts** count characters, not JavaScript string indices, which differ for emoji ([ADR 0007](adr/0007-text-properties-faces-and-display-rows.md)).
- **Face heights** (deliberate): a whole number is an absolute height and a number with a fraction a factor, as Emacs reads them, but a script cannot write the factor 2.0 apart from 2 ([ADR 0029](adr/0029-redisplay-beyond-rows.md)).

## Keys and the command loop

- **`max-mini-window-height`** of 1 lets the minibuffer take the whole frame, as 1.0 does in Emacs, where an integer 1 means one line: E8's numbers do not tell integers from floats, and vertico's 1.0 must mean the frame.
- **`read-key-sequence` and ESC** (not yet): ESC then x reads as `M-x`, where Emacs's gives the two keys `ESC x`. `read-key` takes ESC alone, as Emacs does.
- **Abbrevs** (not yet) are not saved to `abbrev_defs` between sessions, a mode's table does not inherit its parent mode's, and `list-abbrevs` shows only the tables that have been used, where Emacs shows every mode's ([ADR 0040](adr/0040-everyday-editing-commands.md)).
- **`M-x diff`** (not yet) runs diff to the end before showing `*Diff*`, where Emacs shows its output as it comes, and diff-mode cannot apply, split or refine hunks ([ADR 0040](adr/0040-everyday-editing-commands.md)).
- **Highlighting by regexp** (not yet) always uses overlays, as Emacs does only in buffers without font-lock rules, so new text is not highlighted as it is typed; `hi-lock-file-patterns`, `hi-lock-write-interactive-patterns` and the big `hi-black-hb` face are missing.
- **The buffer list** (not yet): `t`, the `M-s a` searches and grouping (`Buffer-menu-group-by`) are missing ([ADR 0040](adr/0040-everyday-editing-commands.md), [ADR 0041](adr/0041-header-line-and-tabulated-lists.md)).
- **The header line and tabulated lists** (not yet): a click on the header line is not a `<header-line> <mouse-1>` event, so clicking a column title does not sort by it (`S` does); `header-line-indent-mode` does not follow the line numbers' width; tabulated lists have no groups (`tabulated-list-groups`); and a cut column ends in `…` whether or not the terminal can show it, where Emacs falls back to `...` ([ADR 0041](adr/0041-header-line-and-tabulated-lists.md)).
- **`undo-only`** (not yet) passes over the last undo and the change it undid once, as Emacs's does when its `undo-equiv-table` finds them. After a command that failed, Emacs's finds nothing, as the failure leaves an undo boundary, and redoes as `undo` would; E8's still passes over them.
- **`C-c C-,`** (not yet) lists Org's block templates in the minibuffer's prompt, where Emacs shows them in a window of their own, grouped by first key.
- **Tabs** (not yet): there are no tab groups, `other-tab-prefix` (`C-x t t`), `project-other-tab-command` (`C-x t p`), `tab-bar-select-tab-modifiers`, repeat maps, dragging tabs or the tab bar's context menu; a tab is selected on the click rather than on the press. `tab-bar-history-mode` keeps a command's windows when their buffers change, as there is no `window-configuration-change-hook`, so a resize alone is not kept. The GUI draws the tab bar in its own inks, as it does the mode line, not in the tab-bar faces.
- **Help** (not yet): no tutorial (`C-h t`), Info (`C-h i`) or manual (`C-h r`), which [ADR 0064](adr/0064-the-help-system.md) says will read the user's installed Info files and the online manual rather than ship the GFDL manuals; `describe-key` says nothing of remapping or which keymap bound the key, `describe-bindings` flattens prefix maps into their sections instead of listing each prefix's own, `help-for-help` is a list of the keys rather than Emacs's text, `apropos` matches any one word of a word list, with no scores, and *Help* has no mouse buttons, `help-echo`, `s` to the source or `i` to Info. `describe-symbol` takes its default from a run of name characters, not the syntax table. `C-h f` describes a command or a name made with `e8.defun`, whose documentation E8 does not keep.
- **which-key** (not yet) shows its window along the bottom only, with an empty mode line where Emacs's has none, and cannot page through a long list with `C-h`; `which-key-replacement-alist` is not read beyond turning `<f1>` into `f1`, and `which-key-add-key-based-replacements` names prefixes only.
- **Desktops** (deliberate and not yet): the file is JSON, `.e8.desktop`, where Emacs writes Lisp to `.emacs.desktop`. Only the selected frame's windows are saved, not other frames or tabs, buffers are restored at once rather than lazily, and Dired is the only mode with a handler of its own.
- **EditorConfig** (not yet): `end_of_line` and `charset` are not applied, as E8 does not yet choose a coding system that way; settings apply from `hack-local-variables-hook`, which `normal-mode` runs, as E8 has no file-local variables.
- **Tangling** (not yet): noweb references (`<<name>>`), `:comments` other than no and `org-babel-tangle-use-relative-file-links` are not read, and evaluating blocks (`C-c C-c` on a source block) is not there yet.
- **eglot** (not yet): edits reach the server as the whole text rather than incrementally, there is no signature help, inlay hints, workspace symbols, snippets or events buffer, and one server serves a buffer. What point is on shows in the echo area as hover's first line, as there is no eldoc; diagnostics are overlays with `flymake-goto-next-error`, without flymake's fringe marks or diagnostics buffer.
- **`completion-at-point`** (not yet) asks in the minibuffer when several completions remain, where Emacs completes in the buffer and lists them in `*Completions*`; completion tables are lists, not functions of the input.
- **xref** (not yet) has no etags backend, so `M-.` finds definitions only where a backend such as eglot's is active, and `xref-find-apropos` is missing.
- **Themes** (not yet): `load-theme` asks before running a theme not in `custom-safe-themes` but cannot add it there for later sessions; a theme's face is one set of attributes rather than display conditions; and the GUI draws its own parts, the mode line, header line, tab bar and cursor, in a theme's faces only when they have a background of their own. The `tsconfig.json` E8 writes checks `init.ts`, not the packages in `packages/`, which import E8's own by name.
- **`zap-to-char`** (not yet) reads its character as a key rather than from the minibuffer, so there is no history to go back through ([ADR 0040](adr/0040-everyday-editing-commands.md)).
- **`what-cursor-position`** (not yet) with a prefix argument does not describe the character, as `describe-char` is not there, and shows no character names.
- **`sleep-for`** (not yet): keys typed while a command sleeps run their commands at once, where Emacs keeps them until the command ends.
- **Translation keymaps** (not yet): `input-decode-map` and `key-translation-map` translate the keys the command loop reads, but not those `read-key-sequence` reads partway through a command, and there is no `function-key-map`.
- **`this-command-keys`** (not yet): keys a command reads with `read-event` are not added to it, as Emacs adds them.
- **Disabled commands** (not yet): `upcase-region`, `downcase-region` and the others novice.el disables for new users run straight away.
- **Errors' wording** (deliberate): deleting more characters than there are says "End of buffer", where Emacs reports an internal "Args out of range" naming the buffer. The text is the same in both.

## Text and search

- **Source blocks' faces** (not yet): `org-src-block-faces` is not read, and a block in a language with no mode in E8, such as shell, has only `org-block`. Python blocks have python-ts-mode's faces, which differ in detail from python.el's.
- **`window-configuration-change-hook`** (not yet) runs after a command that changed the selected frame's windows or the buffers they show, not when a window's size changes, nor buffer-locally in each window's buffer, as Emacs runs it at redisplay.
- **Shell scripts** (not yet): `sh-mode` runs `bash-ts-mode` whatever the shell, where Emacs's turns to its own mode for shells other than Bash and sh, and there is no `sh-mode` without the Bash grammar: a bash block in Org then has only `org-block`. Indenting is by tree-sitter rules that put a block's lines `sh-basic-offset` in, where Emacs indents with SMIE, and `sh-mode`'s keys and skeletons are not there.
- **Emacs Lisp mode** (deliberate): E8 cannot run Emacs Lisp, so there is no `C-M-x`, `eval-last-sexp`, byte-compiling or completion of Lisp symbols. How a macro indents comes from a table of the indent specs `emacs -Q` has, not from `declare` forms in the code, so macros of other packages indent as calls. Faces leave out autoload cookies, `\\[command]` and `\\<map>` in doc strings, regexp grouping constructs and ineffective backslashes; characters beyond the Basic Multilingual Plane put the faces after them out of place.
- **Explicitly numbered groups** (deliberate): `\(?N:...\)` takes N up to 65,535 and says "Regular expression too big" above, where Emacs takes N up to 2³¹ − 1; E8's matcher keeps a slot for every group up to the highest.
- **Literal searches** (not yet) fold case by the standard case table, not by a buffer's own; regexp searches follow the buffer's.
- **Case equivalence tables** (not yet): a case table's third extra slot is not worked out.
- **Putting text properties** (not yet) records no undo, does not mark the buffer modified and runs no change hooks, as if Emacs's `with-silent-modifications` were around every call. E8's packages fontify and fold this way, as Emacs's font-lock does inside that macro, so a package that relies on properties being undone does not work yet ([ADR 0034](adr/0034-buffer-and-text-property-primitives.md)).
- **TAB on an entry of only blank lines** (deliberate) folds it again once it is shown, so TAB goes between folded and shown as for an entry with text. Org takes such an entry for folded whether it shows or not, so once TAB has shown it, it says `SUBTREE (NO CHILDREN)` each time and leaves it open; only `S-TAB` or `outline-hide-subtree` fold it. The oracle's `org-folding/blank-entry-*` cases record Org's way.
- **`org-adapt-indentation`** (not yet) is not read: Org's indentation commands indent as if it were nil, so text under a heading is not indented to the heading's text.
- **Indirect buffers** (not yet): Org's `org-indirect-buffer-display` frames are not titled after the heading, and `org-cycle-hook` is not run after `C-c C-x b` ([ADR 0034](adr/0034-buffer-and-text-property-primitives.md)).
- **`buffer-undo-list`** (not yet) counts positions from 0, shows no `(MARKER . ADJUSTMENT)` entries and `(t . TIME)` as `[true]`; a list set from code loses which steps were undos and the markers deletions moved, though binding it to t and back loses nothing. Text property changes are recorded and modify the buffer, but run no change hooks and do not check for read-only text ([ADR 0034](adr/0034-buffer-and-text-property-primitives.md), [ADR 0043](adr/0043-the-undo-list-and-property-changes.md)).
- **Display strings next to each other** (not yet): a `display` property over several characters shows once if the strings are equal, where Emacs shows each character's string apart unless they are the same object. `read-passwd` therefore hides a password with one string of stars, so the cursor shows after them rather than among them when point is moved inside.
- **Faces as attribute lists** in a `face` property, `(:height 1.5)`, are not read (not yet); faces are named.
- **`text-scale-adjust`** (not yet) has no lower limit, where Emacs stops at the smallest font a frame can show.

- **Tree-sitter queries** (not yet) are strings in tree-sitter's syntax; Emacs's Lisp-form queries are not read. In a string, Emacs 30 cannot run its own predicates, `#equal`, `#match` and `#pred`, where E8 can ([ADR 0036](adr/0036-tree-sitter-for-scripts.md)).
- **Tree-sitter and narrowing** (not yet): Emacs parses only the accessible part of a narrowed buffer, E8 all of it, so a node's positions may lie outside the narrowing ([ADR 0036](adr/0036-tree-sitter-for-scripts.md)).
- **Highlighting in tree-sitter modes** (not yet) comes from each shipped grammar's own query, not the mode's `treesit-font-lock-rules`, so faces differ in places from Emacs's; go-ts-mode, whose grammar is loaded from a library, uses Emacs's rules. In those rules a character has one face, so `append` and `prepend` act as `keep` and `t`, and Emacs's own predicates are not checked, only tree-sitter's `#match?` and `#eq?`.

- **Images** (not yet): only a GIF's first frame (or its `:index`) shows, as there is no `image-animate`; `:conversion`, `:heuristic-mask`, `:crop`, `:map` hot spots, `:transform-smoothing` and an SVG's `:foreground`, `:css` and text are not used; PNG, JPEG, GIF and SVG are the only types, where Emacs also has WebP, TIFF, XPM, XBM, PBM and HEIC; and an image wider than the window is clipped at its edge rather than cropped to leave room for the cursor ([ADR 0046](adr/0046-images.md)).
- **The same image twice** (not yet): two pieces of text next to each other with equal image specs show the image once, as with display strings, where Emacs shows two unless the specs are the same object. So two `insert-image`s of one image, side by side, show one.
- **Image masks and metadata** (deliberate): as on Emacs's Mac port, an image's transparency stays in the image, so `image-mask-p` is true only with a `:mask`, and a GIF's metadata is `(delay SECONDS count FRAMES)`, without X's `extension-data`.
- **`max-image-size`** (deliberate): a script cannot write 10.0 apart from 10, so a whole number below 100 is a ratio of the frame's size, as Emacs reads a float, and one of 100 or more a limit in pixels.
- **Failed images** (not yet): an image that could not be loaded is not tried again at each redisplay, as Emacs tries it, until `image-flush` or `clear-image-cache`.
- **`image-mode`** (not yet) shows the image shrunk to fit and has `+`, `-`, `r`, `h`, `v` and `q`, but none of image-mode.el's other commands: no `C-c C-c` to see the bytes, no scrolling across a large image, no next and previous file, no animation, no fitting to the window's height or width on demand. The file's bytes are hidden behind the image with an `invisible` property, where Emacs's display property covers them. The image commands change an image at once, where Emacs waits for 0.3 seconds of idle time to batch them.
- **Display tables** (not yet): only the selective-display slot of `buffer-display-table` and `standard-display-table` is drawn, the string hidden text with an ellipsis shows as, and it holds a string, its faces as text properties, where Emacs's holds a vector of glyphs; the characters' own entries are not used.
- **Spell checking** (deliberate and not yet): ispell.ts runs the checker once for each check, where ispell.el keeps one running, so words accepted for the session are sent again each time. `C-c $` chooses a correction with the minibuffer, not a popup menu, and words typed with a self-inserting command are checked after `flyspell-delay` seconds idle by a timer rather than `sit-for`. In tree-sitter modes, whose faces are not text properties, `flyspell-prog-mode` checks words that the syntax table puts in comments and strings. `ispell-word` has no `l` (look up), `u`, `m` or `?` help in `*Choices*`, and there is no `ispell-buffer` or `ispell-region` yet; flyspell does not change abbrevs (`flyspell-abbrev-p`).
- **org-agenda** (not yet): `*Agenda Commands*` lists Org's views, but only `a` and `t` run; the others say E8 does not have them yet, and there are no custom agenda commands.
- **org-capture** (not yet): only entries are captured, to `file`, `file+headline`, `file+olp` and `file+olp+datetree` targets; of the options only `:tree-type`, `:clock-in` and `:clock-resume` are read; `%a` links an Org heading by its title or another file's line by its text, where `org-store-link` asks the mode; and other escapes, `%^{prompt}`, `%k` and the rest, are left as they are.
- **org-clock** (not yet): a clock does not survive quitting E8 (`org-clock-persist`), there is no resolving of idle time or dangling clocks, no clock reports or `org-clock-display`, no effort in the mode line, and `C-u C-c C-x C-i` does not offer recent tasks.
- **Org logging** (not yet): a state that asks for a note, as `WAIT(w@)`, logs the time only, where Org opens `*Org Note*` to write one; notes always go newest first (`org-log-states-order-reversed`), and the `LOG_INTO_DRAWER` and `LOGGING` properties are not read.
- **Org fast tag selection** (not yet): `!` does not turn groups off, there is no expert interface (`org-fast-tag-selection-single-key` `expert`), `org-tag-alist`'s `:startgrouptag` and `:grouptags` are not read, and neither are `#+TAGS:` lines or `org-tag-persistent-alist`; TODO keywords with keys are not offered beside the tags.
- **Org speed commands** (not yet): the keys for `org-goto`, `org-next-block`, `org-previous-block`, `org-columns`, `org-sort`, archiving, `org-inc-effort` and `org-sparse-tree` say E8 does not have those commands yet; `org-speed-commands` entries are [key, command] or [key, [function, ...arguments]], not Lisp forms.
- **org-refile** (not yet): outline paths complete whole, not a level at a time (`org-outline-path-complete-in-steps`); there is no creating parent nodes, `org-log-refile`, refile cache, refiling a region, or `C-u C-u C-c C-w` to the last refiled place.
- **org-indent-mode** (not yet): inline tasks are indented as headings, and the indentation starts at once for the first 50 ms of a buffer and goes on by a timer, where Org's agent waits for idle time. Text yanked from an indented buffer loses its prefixes because `yank-excluded-properties` names `line-prefix` and `wrap-prefix`, where Org takes them off as the text is copied.

## Bidirectional text

E8 reorders text as Emacs 30.2 does, and `tests/emacs/bidi/` compares the two on 281 lines ([ADR 0047](adr/0047-bidirectional-text.md)). Where they differ:

- **Arabic in the GUI** (not yet): letters do not join, as each letter of a right-to-left script is drawn on its own, spaced to its column, so egui's shaper cannot turn the core's visual order around again. On a terminal Emacs does not join them either.
- **Directional controls in the GUI** (not yet): LRM, RLE, LRI and the others show as a space a column wide, as on a terminal, where Emacs's graphical frames show a thin space a pixel wide.
- **Line numbers** (not yet) stay left of a right-to-left row, where Emacs puts them on its right.
- **Strings in bidirectional lines** (not yet): a `(space ...)` display spec is reordered as an object, where bidi.c treats it as a paragraph separator; a display string in several faces is reordered a face at a time; and a line an overlay string with a newline breaks is not reordered.
- **Embeddings inside isolates** (not yet): a PDF that ends an embedding inside an isolate can take the level outside the embedding where bidi.c gives it the level inside, which moves where it shows.
- **The Arabic letter mark**, U+061C (not yet), shows as a space, where Emacs on a terminal shows it as itself.
- **`move-point-visually`** (not yet): on a truncated right-to-left line, and from inside text a display string covers, Emacs lays the line out afresh and lands elsewhere than what it shows suggests; E8 moves by what shows. At the end of the buffer on a wrapped line, Emacs can signal end-of-buffer where E8 stays.
- **A truncated right-to-left line** (not yet) is not scrolled sideways to keep point in view, as left-to-right ones are; its start shows at the right edge.
- **Lines continued with mixed directions** (unverified): moving by screen lines over a line whose rows hold characters from both ends of a run, as visual-order breaking can make, is not compared with Emacs.

## Windows and frames

- **Window starts** (not yet): a window always starts at the start of a line. So in the terminal, `C-v` over continued lines scrolls by lines of text rather than screen rows ([ADR 0029](adr/0029-redisplay-beyond-rows.md)), and an image taller than the window cannot be scrolled through part way, as Emacs's `vscroll` does.
- **`posn-at-point`'s y** (not yet) is the top of the row, where Emacs gives the top of the glyph: below it for text beside a taller image, by the row's ascent less the font's. Emacs gives the row's top for some characters before or just after an image too.
- **Quitting a window** (not yet): `quit-window` does not restore the window's old height, and does not hide a frame made for the buffer, where Emacs iconifies it ([ADR 0028](adr/0028-windows-as-objects.md)).
- **The buffer list** (not yet): frames have no buffer lists of their own, and a buffer made after another was buried comes before it, where Emacs puts it after. `previous-buffer`'s skip options (`switch-to-prev-buffer-skip`, `switch-to-visible-buffer`) are not there.
- **The title bar** (deliberate): on macOS a window's title bar is transparent, taking the theme's background, and the window looks dark or light as that background is, as Emacs's frames do with the `ns-transparent-titlebar` and `ns-appearance` parameters set. Emacs shows the system's title bar unless they are; E8 has no frame parameters to turn it back. Full screen, the frame takes the whole screen.
- **Window configurations** (not yet): a previous-buffer entry a window dropped after the configuration was saved comes back as it was then, not as a marker that followed edits.

## Files and the clipboard

- **Auto-revert** (not yet) polls every `auto-revert-interval` seconds rather than being told by the system ([ADR 0018](adr/0018-files-and-saving.md)).
- **The clipboard** (not yet): X11's primary selection is not used, and the terminal does not write the clipboard ([ADR 0031](adr/0031-the-system-clipboard.md)).
- **Dired** (not yet): `M-DEL` and `* c` read their mark as text and RET, where Emacs reads a key ([ADR 0022](adr/0022-dired-and-projects.md)).
- **Dired** (not yet): `!` offers no guessed command (`dired-guess-shell-alist-default`), `dired-do-query-replace-regexp` visits the files one after another rather than through fileloop, so `M-,` does not go on, and `Z` reports failures in the echo area rather than the `*Dired log*` buffer. wdired does not edit permissions (`wdired-allow-to-change-permissions`), and isearch and query-replace in it search the whole listing, not only the names.
- **`describe-current-coding-system`** (not yet) stops before Emacs's priority list for detecting coding systems and the coding systems it keeps for particular file names, as E8 detects in a fixed order ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **`directory-files`** (not yet) sorts the names even with NOSORT, where Emacs gives the directory's own order ([ADR 0033](adr/0033-file-primitives.md)).
- **File name handlers** (not yet) are asked by the primitives in ADR 0033 and by visiting and saving, but not yet by `expand-file-name`, `file-attributes` or the copying and renaming commands.
- **Raw bytes** (deliberate): bytes that are no text in their coding are the characters U+10FF80 to U+10FFFF, where Emacs's are beyond Unicode at #x3FFF80 to #x3FFFFF. They show and are written back as in Emacs ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **Unibyte strings** (deliberate): scripts hold bytes as strings of characters U+0000 to U+00FF, as Emacs prints unibyte strings, and a string with other characters stands for its UTF-8. So inserting `encodeCodingString`'s result shows Latin-1 letters where Emacs's shows `\303\251` ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **The `charset` text property** (not yet): Emacs puts it on text decoded in a charset's coding and uses it when encoding again. E8 has none, so `iso-2022-7bit` chooses each character's set by the text's script: JIS X 0208 for text with kana, KS C 5601 with Hangul, else GB 2312, where Emacs writes kana alone in GB 2312's set ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **Japanese files without a cookie** (not yet): Shift_JIS and EUC-JP open as Latin-1, as there are no language environments to prefer them; Emacs without a Japanese one opens Shift_JIS as `emacs-mule`, which E8 does not have ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **Saving text the coding cannot write** (not yet) asks for a coding without the `*Warning*` buffer Emacs shows listing the characters; written without asking, from code, it is saved as UTF-8.
- **Imenu** (not yet) makes the index afresh each time, so there is no `*Rescan*` item, and there is no menu bar index ([ADR 0039](adr/0039-imenu.md)).
- **Comint** (not yet) has no prompt regexps (`comint-use-prompt-regexp`) or completion at the prompt, and ANSI colours other than the 256-colour and RGB ones are faces of E8's own rather than face attribute lists ([ADR 0038](adr/0038-comint-and-shell.md)).
- **Standard error** (not yet): `makeProcess`'s `stderr` takes a buffer, as `make-process`'s `:stderr` does, on pipes only; not a pipe process with a filter of its own, and text inserted there runs no change hooks, as a process's output into its buffer runs none in E8.
- **Network connections** (not yet) connect while the command waits; `:nowait`, TLS and datagrams are not there ([ADR 0037](adr/0037-terminals-sockets-and-process-codings.md)).
- **Connecting or listening** (deliberate) asks the agent's permission while it acts, as running a program does.
- **Changing a file's modes or times** (deliberate) asks the agent's permission while it acts, as writing files does; Emacs has no agent to ask.

## Invisible differences

Kept for completeness, as they cannot be seen:

- Show Paren mode's idle timer exists only while the mode is on.
- The standard case and category tables are made as char-tables only when code asks for them.
- An indirect buffer keeps a copy of its base's text, which the editor keeps the same after every change, where Emacs keeps one copy ([ADR 0034](adr/0034-buffer-and-text-property-primitives.md)).
- Fields compare `field` values with `equal`, where Emacs uses `eq`; only two distinct strings with the same text tell them apart.
- **Isearch** (not yet) has no `M-p` and `M-n` through the search ring, `isearch-edit-string`, word, symbol or lax-whitespace search, lazy count, opening of invisible text as it passes, or scrolling while searching; its prompt shows no `isearch-fail` face on what fails to match ([ADR 0042](adr/0042-isearch-state-and-comint-history-search.md)).
- **Faces** (not yet) have no stipples. Double, dotted and dashed underlines draw as plain lines and raised or pressed boxes as plain boxes. `:distant-foreground` is kept but not used. The terminal draws no overline, box or wave, as Emacs on a terminal does not ([ADR 0044](adr/0044-faces-as-emacs-s.md)).
- **Fonts** (not yet): a face draws in any installed family it names, its regular weight only, one frame after it is first named ([ADR 0052](adr/0052-faces-in-installed-fonts.md)); the `default` face's family does not change the window's main font, and there is no `set-frame-font`. `list-fonts` and `x-list-fonts` offer each installed family in regular, bold, italic and bold italic without asking the system which styles exist, and `x-family-fonts` and font capabilities (`:otf`, scripts) are missing. egui keeps no ascent, so an open font's ascent and descent split its line four to one. A script cannot write a float such as `12.0`, so a size in points is `:point-size` ([ADR 0048](adr/0048-overlay-arrows-fringe-indicators-and-fonts.md)).
- **Fringes and margins** (not yet): no `overflow-newline-into-fringe` setting (the cursor at the end of a full line goes in the fringe regardless), no periodic bitmaps, and a top or bottom indicator taller than its row is not carried into the next. One bitmap shows per fringe, the overlay arrow's in place of the left one where Emacs draws it over. Fringes are always 8 points wide, and a defined bitmap's bits are points, so it draws small on a high-density display. The GUI's bell sounds only on macOS; elsewhere egui has no sound, so the frame flashes ([ADR 0045](adr/0045-margins-fringes-and-redisplay-primitives.md), [ADR 0048](adr/0048-overlay-arrows-fringe-indicators-and-fonts.md)).
- **Quitting** (not yet): `C-g` stops a running command at its next safe point, as in Emacs, and the window goes on drawing meanwhile ([ADR 0051](adr/0051-the-editor-thread.md)). Reading and writing files, decoding, `parse-partial-sexp` and sorting do not check for a quit yet. A script's columns after a loop's opening brace are off by the length of the check put there ([ADR 0049](adr/0049-quitting.md)).
- **Wrapping** (not yet): a display string standing for text is never split by wrapping, where Emacs continues it on the next line; a long message in the echo area wraps without the `\` a terminal shows at each break ([ADR 0029](adr/0029-redisplay-beyond-rows.md)).

## Packages and tests

- **Installing packages** (not yet): only from git repositories, as package-vc does, with git on PATH; there are no archives, so no `list-packages` to browse, no `package-install` by name, and no tarball downloads. Upgrading a package takes effect when E8 next starts, as a module once imported is not imported again. Packages are installed in `repos/` beside `init.ts`, where Emacs's go in `elpa/` (deliberate: they are neither Emacs Lisp nor from an archive). There are no autoloads, so `package-vc.ts` is preloaded for its commands ([ADR 0059](adr/0059-packages-are-git-repositories.md)).
- **ERT** (deliberate): `should` is given a value, or a function whose source it shows, not a form, so `shouldEqual` stands for `(should (equal A B))` to show both values; there are no `ert-explain` explanations, no `M-x ert` results buffer commands, and test bodies run without awaiting.
- **acp** (not yet): the client follows acp.el 0.18.2, but its traffic buffer is a line for each message, without acp-traffic.el's browser, and what the agent writes to standard error reaches the error handlers when its output, its end or a quarter-second timer looks at its stderr buffer, where Emacs's after-change hook sees it at once. The process group is signalled only while the agent runs, so children it left behind after exiting are not killed at shutdown. Requests from TRAMP directories are not supported ([ADR 0061](adr/0061-agents-over-acp.md)).
- **agent-shell** (not yet): Claude Code's adapter (`claude-agent-acp`, as of 2026-11-06) reads and writes files with its own tools and asks under Claude Code's own permission settings, so with it E8's buffer-backed `fs/` methods and permission questions go unused, unless it uses E8's own tools, which it is given and which ask ([ADR 0062](adr/0062-agents-through-e8-mcp-ask-first.md)); a buffer with no unsaved changes visiting a file a tool call touched is reverted when the call completes, one with changes is left alone. E8's own Org buffer rather than agent-shell's shell-maker one, after its design, the agent's Markdown converted to Org text rather than shown through overlays as agent-shell's markdown-overlays does; the conversation a transcript as agent-shell's and comint's, the agent's turns and the requests sent read-only and never undone, since an ACP session can take nothing back, while gptel's document model, where the buffer is the conversation and editing it changes what the model sees next, waits for the Messages API backend of one M-x agent: no terminals for the agent, no slash-command completion, no viewport or prompt queue, no images or files attached to a prompt, and a session is not resumed when E8 starts again ([ADR 0061](adr/0061-agents-over-acp.md)). Picking a mode has no key of its own (`M-x agent-shell-set-session-mode`), as agent-shell's `C-c C-m` is `C-c RET`, which sends here; `C-c TAB` cycles the modes as well as agent-shell's `C-<tab>`, which `tab-bar-mode` takes.
- **Batch mode** (not yet): `--batch` runs `-L`, `-l`, `-f` and `--eval`, not Emacs's other options; prompts are not read from standard input, and timers and processes run only while a script waits on them, with `sleepFor`, `sitFor` or `acceptProcessOutput`, which wait without reading input there, as in Emacs.

## Packages

The ports of packages Emacs does not ship, vertico, consult, magit and the rest, are repositories of their own in `e8-editor` ([features](features.md#packages-in-their-own-repositories)), and each lists where it differs from the package it follows in its README, as [e8-vundo](https://github.com/e8-editor/e8-vundo#differences-from-vundoel) does. Here are the packages E8 ships that they build on.

- **transient** (not yet): no help (`?`, `C-h`), saving or setting a prefix's value (`C-x s`, `C-x C-s`) or history (`C-M-p`), levels, edit mode, moving about the menu with the mouse or keys, `transient-switches` with choices to cycle, or `C-z` to suspend. Prefixes and their groups are defined with `transientDefinePrefix` and objects, not Lisp's vectors and lists.
- **org-id** (not yet): there is no `org-id-locations-file`: IDs are found in the Org buffers open, the agenda files and `org-id-extra-files`, or by a package such as org-roam.
- **Ediff** (not yet): only the plain window layout, the control panel in a window below the buffers, as on a terminal; Emacs gives the panel a frame of its own on a graphical display. The panel's window is split off at its size, as E8 does not shrink a window below four lines. Not there yet: comparing directories, regions, windows, revisions and patches, the session registry and group sessions, `~` to swap the buffers, `z`, `i`, `E`, `G`, `R`, `M`, `=`, `m`, `s`, `/`, `v`, `V`, `<`, `>`, `h`, focusing or hiding regions by regexp (`#f`, `#h`), ignoring case (`#c`), quick help on RET or a click, the merge buffer's markers refined when combined, and the merge buffer's mode set again when it is saved. A buffer with no file saved with `wc` or `wd` is asked for one as `File to save in:`, as Emacs's save-buffer asks, rather than E8's `Write file:`. Ediff's windows, faces and fine differences are tested against an interactive Emacs, as batch Emacs, which the oracle runs, has no faces and makes the panel four lines.
