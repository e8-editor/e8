# Where E8 differs from Emacs

E8 behaves as Emacs does, and the oracle in `tests/emacs/` checks it on recorded cases. This page lists where it does not: behaviour E8 has that works differently, either on purpose or because matching Emacs is not done yet. It is the place to look before reporting a difference, and the place to add one when it is found.

It does not list what E8 lacks altogether. That is in [plan.md](plan.md) (the gaps in the core) and in each ADR's consequences. Ideas for doing better than Emacs on purpose, later, are in [departures.md](departures.md). Cases the oracle knows differ are in [`tests/emacs/known-gaps.txt`](../tests/emacs/known-gaps.txt).

Each entry says whether the difference is **deliberate**, which keeps it, or **not yet** fixed.

## How code runs

- **Waiting for input** (deliberate): Emacs's Lisp waits inside `read-key`, `yes-or-no-p`, `read-from-minibuffer` and `recursive-edit` until the answer comes. E8's commands return, and the answer runs code given with the request, which scripts write as `await` ([ADR 0030](adr/0030-the-command-loops-primitives.md)). What the user sees is the same; code after the question runs later rather than in the same call.
- **Keys and events** (deliberate, for now): events are key descriptions, `"C-x"` or `"<mouse-1>"`, not Lisp values carrying their positions. A mouse event's place is the last mouse event's, from `lastMouseEvent` ([ADR 0030](adr/0030-the-command-loops-primitives.md)). Without `track-mouse`, E8 sends `<drag-mouse-1>` as a drag goes, for the region to follow it, where Emacs sends it once at the release. A terminal cannot move the pointer, and `set-mouse-position` there selects the frame, as Emacs without GPM does. `mouse-position` counts from the top left of the frame's windows, below any tab bar, as `window-edges` does. `<mouse-movement>` events are kept out of `recent-keys`, where Emacs keeps the first and last of each run ([ADR 0074](adr/0074-mouse-events-as-emacs-has-them.md)).
- **Strings** (deliberate): JavaScript strings have no unibyte form. So `downcase` of an ASCII-only string follows a buffer's own case table, where Emacs's ignores it ([ADR 0032](adr/0032-character-tables.md)).
- **Buffer primitives** (not yet): `replaceBufferContents` finds every difference, as Emacs's does, up to 2000 deletions and insertions, past which it replaces the part that differs whole; Emacs's limit counts its own way. `bufferLocalVariables` lists the variables a buffer has its own values of, not the per-buffer state E8 keeps outside variables.
- **Overlays in scripts** (deliberate, for now) are numbers, unique among every buffer's, so `overlayBuffer`, `overlayGet` and the rest find an overlay from any buffer, as Emacs's do. A deleted overlay is gone rather than kept in no buffer: `overlayp` is false of it, `copyOverlay` gives undefined, and `moveOverlay` cannot move one to another buffer.
- **Syntax tables in scripts** (deliberate, for now) are names, as `text-mode-syntax-table`, not char-tables: `copySyntaxTable` gives the copy's name, and `stringToSyntax` gives Emacs's raw descriptor as `[code, matching]`, the matching character a string. A copy of the standard table inherits from it, so a later change to the standard table shows through where the copy has no entry of its own; Emacs's copy keeps the entries it had. A copy is never freed, as tables are named, so copying a table on every command, which Emacs's garbage collector makes cheap, keeps each copy.
- **Processes in scripts** (deliberate, for now): processes are objects, as Emacs's are ([ADR 0070](adr/0070-processes-as-emacs-has-them.md)), and every function taking a process takes its name too, while packages move to the objects; asked by name, a process that has gone is not found, as the name may be another's now. Its object's string is its name, and it prints as `#<process NAME>` in JSON and `prin1ToString`. `processFilter` gives the default as `e8.internalDefaultProcessFilter`, a function, where Emacs gives the symbol `internal-default-process-filter`, which E8 also defines. Windows and frames are objects, as Emacs's are ([ADR 0069](adr/0069-windows-as-emacs-has-them.md)); while packages move to them, functions taking a window or frame take its number too.
- **A filter of `t`** (deliberate): Emacs stops reading the process's output until another filter is set; E8 reads on, holding the output back and giving it to the next filter set, in order, on the next look at processes. A process that ends while its filter is `t` loses what was held, as Emacs's leaves it unread. A process that has gone keeps no process mark, so the default filter and sentinel insert nothing for it.
- **Positions in scripts** count characters, not JavaScript string indices, which differ for emoji ([ADR 0007](adr/0007-text-properties-faces-and-display-rows.md)).
- **Face heights** (deliberate): a whole number is an absolute height and a number with a fraction a factor, as Emacs reads them, but a script cannot write the factor 2.0 apart from 2 ([ADR 0029](adr/0029-redisplay-beyond-rows.md)).

## Keys and the command loop

- **`read-variable`** offers every variable, where Emacs offers only user options (`custom-variable-p`): E8 does not tell user options from other variables. `internal-complete-buffer`'s predicate is given `[name, buffer]` where Emacs gives the cons `(NAME . BUFFER)`, and the table ignores `completion-regexp-list`. Of a list of defaults, `read-variable` offers only the first, and a default naming no variable is not taken on empty input, as `completingRead` with `requireMatch` takes no answer outside its collection, where Emacs's takes the default. `abort-minibuffers` tells each command waiting on a minibuffer it quits with `minibuffer-quit`, which that command can catch and carry on from, where Emacs unwinds the levels with a throw nothing catches ([ADR 0083](adr/0083-the-minibuffers-odds-as-emacs-has-them.md)).
- **Keymaps as values** (not yet): a keymap binds its keys in key order, so `accessibleKeymaps` and `keymapBindings` list them that way where Emacs lists the latest bound first. There are no composed keymaps: after `composeLocalMap`, as icomplete does in the minibuffer, `currentLocalMap` is the keymap put in front, so `local-set-key` there changes that keymap wherever it is used, where Emacs's adds the binding to the composed keymap alone. Prefix maps are keymaps rather than prefix commands, so `copyKeymap` keeps those a variable names, as `ctl-x-4-map`, shared, as Emacs keeps a prefix command's, where Emacs copies a keymap bound directly.
- **The window tree's rest** ([ADR 0077](adr/0077-frames-and-the-window-tree-as-emacs-has-them.md)): a window's fringes are its own, in the front end's units, and the layout obeys them; on a terminal `set-window-fringes` does nothing and gives nil, as Emacs's does for a frame that is no window frame. There are no scroll bars: `set-window-scroll-bars` remembers what it is told and `window-scroll-bars` gives it back with widths of 0, as a terminal's window answers. `window-tab-line-height` is 0, there being no tab lines, and a divider's width is its frame's parameter, 0 unless set. What a window was "at the last redisplay" is written down again only when something other than point changed, as Emacs writes it down when a window change happened; `window-old-point` is an offset where Emacs keeps a marker, and `window-old-buffer` never answers `t` for a window a configuration brought back. `window-display-table` and `set-window-display-table` are missing: E8 honours only a display table's selective-display slot, so a table set on a window would change nothing.
- **Terminals** ([ADR 0077](adr/0077-frames-and-the-window-tree-as-emacs-has-them.md)): there is one, which every frame is on, where Emacs's daemon has one for each client; `terminal-list` gives it alone and `delete-terminal` refuses to delete it unless forced, which leaves the editor with nothing to draw on and asks it to exit. `terminal-name` is the tty's device where a front end knows one and `"display"` in a window, where Emacs names the display; `tty-display-color-cells` is read from `TERM` (8, 256 or 16 million) rather than from terminfo. `make-terminal-frame` makes a frame on the one terminal and leaves it unselected, as Emacs's does, with the terminal's `tty` and `tty-type` among its parameters. `suspend-tty` stops the editor, as `suspend-emacs` does, where Emacs's only lets go of the device and leaves the process running, and the terminal is the editor's again when the shell continues it.
- **Frames' geometry** ([ADR 0077](adr/0077-frames-and-the-window-tree-as-emacs-has-them.md)): a frame's sizes are in the front end's units — points in the window, characters on a terminal — where Emacs counts pixels, and `frame-text-width` is what the windows and echo area divide, which is what the front end tells the editor. `set-frame-position`, `set-frame-size`, `set-frame-width` and `set-frame-height` leave the front end a request it carries out as it draws, so the new size is not there the moment they return; a terminal cannot move or resize itself and drops them, as Emacs's do nothing on a text terminal. `frame-native-width` is the text size until a front end says otherwise. There are no child frames, so `frame-ancestor-p` is nil and `frame-child-frame-border-width` is undefined, and no scroll bars, so their widths are 0. `lower-frame` asks the front end and leaves the frames' order alone, as `Flower_frame` leaves `frame-list` alone, but nothing comes of it in the window: egui can raise a window and not lower one. `x-get-resource` is nil, E8 reading no resource database; `x-parse-geometry` reads what XParseGeometry reads, and gives `-0`, the far edge itself, as `["-", 0]` where Emacs gives `(left - 0)`. `modify-frame-parameters` with `width`, `height`, `left` or `top` records the value and does not move or resize the frame, where Emacs's does; what `frame-parameters` reports for them is what the frame really is, as Emacs's is. `old-selected-frame` is the frame selected at the last redisplay, where Emacs's is the one selected when window change functions last ran, which E8 does not have.
- **Menus** ([ADR 0076](adr/0076-menus-as-emacs-has-them.md)): E8 draws its menus itself, as cells over the windows, in a terminal and in the GUI alike, so they look like E8 rather than like the platform's menus. A menu keymap's items show in the order they were bound, where Emacs's keymaps are alists whose newest binding comes first, so Emacs's own menu code defines them backwards; binding one again keeps its place. A menu item's `:enable`, `:visible`, `:button` and `:filter` hold a value or a function to call, where Emacs holds a form to evaluate, and its `:label` is the label itself, as a script can compute one before binding it. `xPopupMenu` is given a position (`"mouse"`, `"point"` or `[x, y]` in columns and lines) rather than an event, and gives back the keys that reach the item as a string, `"<more> <quit>"`, to look up with `lookupKey`, where Emacs gives a list of event symbols; with no position it shows the menu at the pointer, where Emacs's only precomputes key equivalents, which E8 looks up as the menu opens. Those equivalents are the keys that run the command, plain characters preferred, without Emacs's cache. A menu `"mouse"` opened counts as one the mouse opened, so leaving it gives nothing where Emacs quits for every position but a real click event. `C-g` and `ESC` always leave a menu, whatever `menu-navigation-map` binds them to, since the menu reads its keys one event at a time. The properties `:image`, `:rtl`, `:help-echo`, `:key-sequence` as a check and `:suffix` are missing, and so are a keymap's prompt string as the menu's title and Emacs's old `(STRING . DEFINITION)` item format. A menu item is not listed by `keymapBindings` or offered by `whereIs`, where Emacs's describe-bindings lists them in a section of their own. E8 shows no menu bar until `menu-bar-mode` is on, where Emacs shows one by default in a window and on a terminal; the menus it holds are a subset of `menu-bar.el`'s, with the commands E8 has. The Buffers menu is made again only when the buffers it lists have changed, and never while a menu is open, where Emacs's `menu-bar-update-buffers` asks `frame-or-buffer-changed-p` the same question; a `menu-bar-update-hook` function that fails stops the ones after it, where Emacs's `safe-run-hooks` takes the failing one off the hook and runs the rest. `easyMenuDefine` takes the name the menu bar goes by, where Emacs's `easy-menu-define` takes the variable to define and binds under a name made from it. A dialog is a menu in the middle of the frame, as menu.c's `emulate_dialog_with_menu` shows one where the display has no dialog box; `x-popup-dialog`'s HEADER, which names Emacs's dialog window, is taken and set aside, and where Emacs puts the items before a nil on the left of the box and the rest on the right, E8 draws a line between them. `x-select-font` asks in the minibuffer over the font families the front end has, not in a font chooser. A tooltip is a box E8 draws over the windows, in a terminal as in the window, and nothing shows one by itself: Emacs's `tooltip-mode` shows what a `help-echo` property says when the pointer rests on it, and E8 has no `help-echo`, so a package shows one with `tooltipShow`. `next-read-file-uses-dialog-p` is always nil, there being no file dialog. `tooltip.ts` has the mode, `tooltipShow` and `tooltipHide` and the variables they read, not gud's helpers (`tooltip-start-delayed-tip`, `tooltip-identifier-from-point` and the rest), and its offsets are columns and lines where Emacs's are pixels.
- **Keys that are symbols** ([ADR 0076](adr/0076-menus-as-emacs-has-them.md)): a name in angle brackets that is no key of E8's own, `<menu-bar>` or `<f0>`, is a symbol event, as Emacs reads one, so a key sequence of them can be bound and looked up but never typed. Emacs's `<tab-bar>` has a key of its own in E8 still.
- **`max-mini-window-height`** of 1 lets the minibuffer take the whole frame, as 1.0 does in Emacs, where an integer 1 means one line: E8's numbers do not tell integers from floats, and vertico's 1.0 must mean the frame.
- **`read-key-sequence` and ESC** (not yet): ESC then x reads as `M-x`, where Emacs's gives the two keys `ESC x`. `read-key` takes ESC alone, as Emacs does.
- **Abbrevs**: `abbrev_defs` is in the configuration directory, `~/.config/e8/abbrev_defs`, as `abbrev-file-name` says, and is read by E8 itself rather than loaded as Lisp, so it takes the `define-abbrev-table` forms Emacs writes and passes over any other Lisp in the file; an abbrev's hook is kept and run after it expands if E8 has a function of that name, and properties other than `:count` and `:case-fixed` are left out (deliberate). `list-abbrevs` shows only the tables that have been used, where Emacs shows every mode's, and there are no minor-mode abbrev tables (`abbrev-minor-mode-table-alist`) (not yet) ([ADR 0040](adr/0040-everyday-editing-commands.md)).
- **`M-x diff`** (not yet) runs diff to the end before showing `*Diff*`, where Emacs shows its output as it comes, and diff-mode cannot apply, split or refine hunks ([ADR 0040](adr/0040-everyday-editing-commands.md)).
- **Highlighting by regexp** (not yet) always uses overlays, as Emacs does only in buffers without font-lock rules, so new text is not highlighted as it is typed; `hi-lock-file-patterns`, `hi-lock-write-interactive-patterns` and the big `hi-black-hb` face are missing.
- **The buffer list** (not yet): `t` (no tags tables), `M-s a C-s` and `M-s a C-M-s` (no multi-buffer isearch, misearch.el) and grouping (`Buffer-menu-group-by`) are missing; `M-s a C-o` is there, though `occur` and its kin show no context lines around a match (`list-matching-lines-default-context-lines`, a numeric prefix argument) and do not collect with `C-u` ([ADR 0040](adr/0040-everyday-editing-commands.md), [ADR 0041](adr/0041-header-line-and-tabulated-lists.md)).
- **The header line and tabulated lists** (not yet): a click on the header line is not a `<header-line> <mouse-1>` event, so clicking a column title does not sort by it (`S` does); `header-line-indent-mode` does not follow the line numbers' width; tabulated lists have no groups (`tabulated-list-groups`); and a cut column ends in `…` whether or not the terminal can show it, where Emacs falls back to `...` ([ADR 0041](adr/0041-header-line-and-tabulated-lists.md)).
- **`undo-only`** (not yet) passes over the last undo and the change it undid once, as Emacs's does when its `undo-equiv-table` finds them. After a command that failed, Emacs's finds nothing, as the failure leaves an undo boundary, and redoes as `undo` would; E8's still passes over them.
- **Tabs** (not yet): there are no tab groups, `other-tab-prefix` (`C-x t t`), `project-other-tab-command` (`C-x t p`), `tab-bar-select-tab-modifiers`, repeat maps, dragging tabs or the tab bar's context menu; a tab is selected on the click rather than on the press. `tab-bar-history-mode` keeps a command's windows when their buffers change, as there is no `window-configuration-change-hook`, so a resize alone is not kept. The GUI draws the tab bar in its own inks, as it does the mode line, not in the tab-bar faces.
- **Help** (not yet): no tutorial (`C-h t`), Info (`C-h i`) or manual (`C-h r`), which [ADR 0064](adr/0064-the-help-system.md) says will read the user's installed Info files and the online manual rather than ship the GFDL manuals; `describe-key` says nothing of remapping or which keymap bound the key, `describe-bindings` flattens prefix maps into their sections instead of listing each prefix's own, `help-for-help` is a list of the keys rather than Emacs's text, `apropos` matches any one word of a word list, with no scores, and *Help* has no mouse buttons, `help-echo`, `s` to the source or `i` to Info. `describe-symbol` takes its default from a run of name characters, not the syntax table. `C-h f` describes a command or a name made with `e8.defun`, whose documentation E8 does not keep. `symbol-file` names a package E8 ships by its file in E8's source (`packages/files.ts`), which is not on disk; without a kind it looks at the function, then the variable, then the face, where Emacs takes whichever the most recently loaded file defined; and E8 keeps no `load-history` (not yet; [ADR 0075](adr/0075-compression-and-tls-as-emacs-has-them.md)).
- **TLS** ([ADR 0075](adr/0075-compression-and-tls-as-emacs-has-them.md)): E8's TLS is rustls, under GnuTLS's names. It has no anonymous credentials (`gnutls-anon`), priority strings, CRLs or minimum prime bits, which are taken and set aside (deliberate); TLS 1.2 and 1.3 only, with AEAD ciphers. `gnutls-boot` always waits for its handshake, as with `:complete-negotiation` (not yet: `:nowait`). The system's authorities come from its PEM bundle, `/etc/ssl/cert.pem` on macOS, so authorities added to the macOS keychain by hand are not trusted unless in `gnutls-trustfiles` (deliberate: the keychain takes seconds to read). `gnutls-format-certificate` gives GnuTLS's headings with fewer details. A certificate the handshake itself cannot read, such as an X.509 version 1 one, fails the connection where GnuTLS would let the Network Security Manager ask. Of nsm.el, E8 makes the checks its TLS can fail, the certificate and a pinned key; the others look for ciphers, key exchanges and protocols rustls never offers. It keeps what was accepted for good as JSON in `network-security.json` rather than Lisp in `network-security.data`, and asks with a plain prompt (always, session, no) rather than nsm.el's choices with certificate pages. A refusal names what was wrong (`unknown-ca`) where GnuTLS gives its verification code in hex. Once a connection has closed, `gnutls-peer-status` answers nil and `gnutls-get-initstage` 0, where Emacs keeps the session until `gnutls-deinit`. `open-network-stream` has no STARTTLS (`:type starttls`, or `:capability-command` with `:success`), shell connections or `:nowait`, and signals an error for them rather than opening a connection without encryption (not yet). `gnutls-ciphers` lists the AEAD ciphers only (CHACHA20-POLY1305, AES-128-GCM, AES-256-GCM), where GnuTLS also has CBC and the rest, so `gnutls-symmetric-encrypt` puts the tag after the text and its nonce is 12 bytes; `gnutls-macs` and `gnutls-digests` are the hashes `secure-hash` has, without GOST and STREEBOG, and take a name, where Emacs also takes a symbol, a number or the plist (deliberate). Where Emacs tells a unibyte string from a multibyte one, E8 cannot, so its GnuTLS functions take bytes, as `secure-hash`'s `binary` gives them and as each gives back, and refuse text that is not: a MAC is the key of the next, as SCRAM chains them, and text is encoded first with `encodeCodingString`. `secure-hash` and `md5` take text, as Emacs's do. `iv-auto` is an empty nonce. The last cipher `gnutls-ciphers` gives is AES-256-GCM, where GnuTLS's is AES-256-CBC, so what one obfuscates with `auth-source--obfuscate` the other cannot read.
- **Bytes in buffers** (deliberate): E8 has no unibyte buffers, so `zlib-decompress-region` takes the region's characters as bytes (ASCII and raw bytes), refusing other text where Emacs refuses a multibyte buffer, and inserts what it decompresses as raw bytes; a failure leaves the buffer unmodified, where Emacs marks it modified ([ADR 0075](adr/0075-compression-and-tls-as-emacs-has-them.md)).
- **which-key** (not yet) shows its window along the bottom only, with an empty mode line where Emacs's has none, and cannot page through a long list with `C-h`; `which-key-replacement-alist` is not read beyond turning `<f1>` into `f1`, and `which-key-add-key-based-replacements` names prefixes only.
- **Desktops** (deliberate and not yet): the file is JSON, `.e8.desktop`, where Emacs writes Lisp to `.emacs.desktop`. Only the selected frame is saved: its windows, as `window-state-get` with WRITABLE gives them, printed as Lisp in the JSON (desktops saved before are still read), and in the GUI its place and its text area's size in pixels, which come back only in the GUI, where Emacs keeps its frame parameters and puts a frame from a terminal on a window too. Not other frames or tabs, nor whether the frame was full screen, as E8's frames have no `fullscreen` yet, and a frame saved on a monitor no longer there is not moved back onto the screen (`desktop-restore-forces-onscreen`); buffers are restored at once rather than lazily, and Dired is the only mode with a handler of its own.
- **`expand-file-name`** (not yet): a `//` or `/~/` in the name starts over from the root or the home directory, as `substitute-in-file-name` does for what is typed in the minibuffer, where Emacs's `expand-file-name` collapses the doubled slash and keeps `~` as it is.
- **EditorConfig** (deliberate): `end_of_line` and `charset` give the coding system a file is read and written in through `auto-coding-functions`, as in Emacs 30, which E8 asks with the file's name before its text is read (see "Coding found by functions"); the rest applies from `hack-local-variables-hook`, as in Emacs.
- **File-local variables** (deliberate and not yet): E8 has no Lisp, so an `eval:` entry runs only `setq`, `setq-local`, `progn`, `add-hook`, `remove-hook` and calls of functions and commands with constant or quoted arguments, as `(auto-fill-mode)`; anything else is an error, reported as "File local-variables error". Answering `!`, `i` or `+` to the question about unsafe values adds them to `safe-local-variable-values`, `ignored-local-variable-values` or `safe-local-variable-directories` for the session, where Emacs saves them with customize. There are no connection-local variables yet, and a major mode is chosen from the `-*-` line, the Local Variables list and `auto-mode-alist`, without `interpreter-mode-alist` or `magic-mode-alist`, so a file starting `#!/bin/sh` is not put in a shell mode. Values are Lisp data as E8 holds it: a dotted pair, `(a . b)`, reads as a list of two, as E8's alists are written, and a float with no fraction, as `10.0`, is the integer. So in `.dir-locals.el` `(var . (1 2))` gives the list `(1 2)` but `(var . (1))` gives `1`, and `(eval . FORM)` always takes FORM as a form. `add-dir-local-variable` writes values with `prin1` where Emacs uses `pp`, which differs only for long lists.
- **Tangling** (not yet): noweb references (`<<name>>`), `:comments` other than no and `org-babel-tangle-use-relative-file-links` are not read. `org-babel-tangle-file` as a command takes only the file; code passes a target file and a language regexp to `tangleFile` from `ob-tangle`.
- **Running source blocks** ([ADR 0111](adr/0111-typescript-mode-and-literate-configuration.md)): `C-c C-c` runs TypeScript blocks, in the editor, as Emacs runs Emacs Lisp ones, and `org-babel-load-file` loads a file's TypeScript where Emacs's loads its Emacs Lisp. No other language runs yet, and `:results output`, `:var`, `:cache`, sessions and `:file` are not read.
- **warnings** (not yet): a warning before init.ts has loaded is shown at once, where Emacs keeps it until startup ends (`delay-warning`); `warning-series` is not read; the ⛔ button's answers set `warning-suppress-types` or `warning-suppress-log-types` for the session, where Emacs saves them with customize; and the window showing `*Warnings*` is not fitted to it.
- **eglot** (not yet): edits reach the server as the whole text rather than incrementally, which [performance.md](performance.md) measured as costing under a millisecond; there is no signature help, inlay hints, workspace symbols, snippets (E8 tells servers it takes none, as Emacs's eglot does without yasnippet); completion items with the same text are listed once, with the first one's detail and edits, where Emacs keeps each; and the `eglot-capf` category has no default style of its own, where Emacs's matches with `eglot--dumb-flex` on each item's `filterText` unless `completion-category-defaults` is cleared, as orderless's setup clears it or events buffer, and one server serves a buffer. What point is on shows in the echo area as hover's first line, as there is no eldoc; diagnostics are overlays with `flymake-goto-next-error`, without flymake's fringe marks or diagnostics buffer.
- **`completion-at-point`** (not yet) completes in the buffer and lists what remains in `*Completions*`, with annotations, the table's sort and cycling by `completion-cycle-threshold`, as Emacs does, but a completion table is a list or a function of nothing, not a function of the input, predicate and action: what Emacs's table gives as its metadata, a completion function gives after its list, with `:display-sort-function` and `:cycle-sort-function` beside `:annotation-function`, `:group-function` and `:exit-function`. `*Completions*` shows no affixations, and the minibuffer still shows its own list, drawn by E8. The candidate moved to is marked with an overlay, where Emacs uses `cursor-face`. A completion style a package adds completes to its only match and leaves the text alone for several, as orderless does, having no try-completion function of its own.
- **xref** (not yet) has no etags backend, so `M-.` finds definitions only where a backend such as eglot's is active, and `xref-find-apropos` is missing.
- **Themes** (not yet): `load-theme` asks before running a theme not in `custom-safe-themes` but cannot add it there for later sessions; a theme's face is one set of attributes rather than display conditions; and the GUI draws its own parts, the mode line, header line, tab bar and cursor, in a theme's faces only when they have a background of their own. The `tsconfig.json` E8 writes checks `init.ts`, not the packages in `packages/`, which import E8's own by name.
- **`describe-char`** (not yet): `C-u C-x =` and `describe-char` show what Emacs's do in a terminal, but describe-char does not look at compositions or display tables, and shows no input method's keys under "to input", as E8 has no input methods, and no `describe-char-unicodedata-file` lines; the charset and code point are text rather than buttons, and the overlays at the position are not put on the character it shows.
- **`sleep-for`** (not yet): keys typed while a command sleeps run their commands at once, where Emacs keeps them until the command ends.
- **Translation keymaps** (not yet): `input-decode-map` and `key-translation-map` translate the keys the command loop reads, but not those `read-key-sequence` reads partway through a command, and there is no `function-key-map`.
- **`this-command-keys`** (not yet): keys a command reads with `read-event` are not added to it, as Emacs adds them.
- **Disabled commands** (deliberate): the commands Emacs 30 disables for new users ask first, from a key or M-x, as novice.el's `disabled-command-function` asks; `y` writes `e8.put("COMMAND", "disabled", false);` into init.ts, where Emacs writes `(put 'COMMAND 'disabled nil)` into its init file. A headless e8-mcp, where no one could answer, asks nothing, as if `!` had been answered. `read-multiple-choice`'s question shows in the echo area without the faces on its keys, as E8's messages are plain text (not yet).
- **Errors' wording** (deliberate): deleting more characters than there are says "End of buffer", where Emacs reports an internal "Args out of range" naming the buffer. The text is the same in both.
- **Quick help** (deliberate, [ADR 0068](adr/0068-quick-help-for-newcomers.md)): `help-guide-mode`, on by default, binds `C-h h`, Emacs's `view-hello-file`, which E8 does not have, to a short guide to the current mode, and `C-h 8` to one on getting started; at startup the echo area names them where Emacs's names `C-h C-a`, and agent-shell names `C-h h` when a session starts. Turning the mode off (`e8.callWithPrefix(-1, "help-guide-mode")`) leaves Emacs's help alone.

## Text and search

- **`lineBeginningPosition` and `lineEndPosition` given a position** (deliberate): at point they stop at a field's edge on the line, as Emacs's `line-beginning-position` does after a shell's prompt; given a position, which Emacs's do not take, they do not, as `posBol` and `posEol` never do.
- **Source blocks' faces** (not yet): `org-src-block-faces` is not read, and a block in a language with no mode in E8, such as shell, has only `org-block`. Python blocks have python-ts-mode's faces, which differ in detail from python.el's.
- **`window-configuration-change-hook`** (not yet) runs after a command that changed the selected frame's windows or the buffers they show, not when a window's size changes, nor buffer-locally in each window's buffer, as Emacs runs it at redisplay.
- **Shell scripts** (not yet): `sh-mode` runs `bash-ts-mode` whatever the shell, where Emacs's turns to its own mode for shells other than Bash and sh, and there is no `sh-mode` without the Bash grammar: a bash block in Org then has only `org-block`. Indenting is by tree-sitter rules that put a block's lines `sh-basic-offset` in, where Emacs indents with SMIE, and `sh-mode`'s keys and skeletons are not there.
- **Emacs Lisp mode** (deliberate): E8 cannot run Emacs Lisp, so there is no `C-M-x`, `eval-last-sexp`, byte-compiling or completion of Lisp symbols. How a macro indents comes from a table of the indent specs `emacs -Q` has, not from `declare` forms in the code, so macros of other packages indent as calls. Faces leave out autoload cookies, `\\[command]` and `\\<map>` in doc strings, regexp grouping constructs and ineffective backslashes; characters beyond the Basic Multilingual Plane put the faces after them out of place.
- **Explicitly numbered groups** (deliberate): `\(?N:...\)` takes N up to 65,535 and says "Regular expression too big" above, where Emacs takes N up to 2³¹ − 1; E8's matcher keeps a slot for every group up to the highest.
- **Literal searches** (not yet) fold case by the standard case table, not by a buffer's own; regexp searches follow the buffer's.
- **Case equivalence tables** (not yet): a case table's third extra slot is not worked out.
- **Putting text properties** (not yet) records no undo, does not mark the buffer modified and runs no change hooks, as if Emacs's `with-silent-modifications` were around every call. E8's packages fontify and fold this way, as Emacs's font-lock does inside that macro, so a package that relies on properties being undone does not work yet ([ADR 0034](adr/0034-buffer-and-text-property-primitives.md)).
- **TAB on an entry of only blank lines** (deliberate) folds it again once it is shown, so TAB goes between folded and shown as for an entry with text. Org takes such an entry for folded whether it shows or not, so once TAB has shown it, it says `SUBTREE (NO CHILDREN)` each time and leaves it open; only `S-TAB` or `outline-hide-subtree` fold it. The oracle's `org-folding/blank-entry-*` cases record Org's way.
- **`buffer-undo-list`** (not yet) counts positions from 0, shows no `(MARKER . ADJUSTMENT)` entries and `(t . TIME)` as `[true]`; a list set from code loses which steps were undos and the markers deletions moved, though binding it to t and back loses nothing. Text property changes are recorded and modify the buffer, but run no change hooks and do not check for read-only text ([ADR 0034](adr/0034-buffer-and-text-property-primitives.md), [ADR 0043](adr/0043-the-undo-list-and-property-changes.md)).
- **Display strings next to each other** (not yet): a `display` property over several characters shows once if the strings are equal, where Emacs shows each character's string apart unless they are the same object. `read-passwd` therefore hides a password with one string of stars, so the cursor shows after them rather than among them when point is moved inside.
- **`text-scale-adjust`** (not yet) has no lower limit, where Emacs stops at the smallest font a frame can show.

- **Tree-sitter queries** (deliberate): in a string query, Emacs 30 cannot run its own predicates, `#equal`, `#match` and `#pred`, where E8 can ([ADR 0036](adr/0036-tree-sitter-for-scripts.md)). In a Lisp-form query a vector, `[...]`, is written as an array whose first element is `Symbol.for("[")`, as JavaScript has no vector. A compiled query used on a node of another language is `treesit-query-error`, where Emacs hands it to tree-sitter ([ADR 0084](adr/0084-tree-sitters-rest-as-emacs-has-it.md)).
- **Tree-sitter notifiers and errors** (deliberate): a parser's notifiers are called after the tree-sitter primitive that parsed again, or for a parse highlighting made, after the next primitive or the end of the next command, whose own edits may by then have moved the positions they are told. A primitive called from a jit-lock function runs them inside redisplay, as Emacs's fontification does. Emacs 30.2 never defines `treesit-predicate-not-found` as an error, so `condition-case` on `error` lets it through; E8 makes it a `treesit-error`, as treesit.c's other errors are ([ADR 0084](adr/0084-tree-sitters-rest-as-emacs-has-it.md)).
- **Tree-sitter and narrowing** (not yet): Emacs parses only the accessible part of a narrowed buffer, E8 all of it, so a node's positions may lie outside the narrowing ([ADR 0036](adr/0036-tree-sitter-for-scripts.md)).
- **Highlighting in tree-sitter modes** (not yet) comes from each shipped grammar's own query, not the mode's `treesit-font-lock-rules`, so faces differ in places from Emacs's; go-ts-mode, whose grammar is loaded from a library, uses Emacs's rules. In those rules a character has one face, so `append` and `prepend` act as `keep` and `t`, and Emacs's own predicates are not checked, only tree-sitter's `#match?` and `#eq?`.

- **Images** (not yet): only a GIF's first frame (or its `:index`) shows, as there is no `image-animate`; `:conversion`, `:heuristic-mask`, `:crop`, `:map` hot spots, `:transform-smoothing` and an SVG's `:foreground`, `:css` and text are not used; PNG, JPEG, GIF and SVG are the only types, where Emacs also has WebP, TIFF, XPM, XBM, PBM and HEIC; and an image wider than the window is clipped at its edge rather than cropped to leave room for the cursor ([ADR 0046](adr/0046-images.md)).
- **The same image twice** (not yet): two pieces of text next to each other with equal image specs show the image once, as with display strings, where Emacs shows two unless the specs are the same object. So two `insert-image`s of one image, side by side, show one.
- **Image masks and metadata** (deliberate): as on Emacs's Mac port, an image's transparency stays in the image, so `image-mask-p` is true only with a `:mask`, and a GIF's metadata is `(delay SECONDS count FRAMES)`, without X's `extension-data`.
- **`max-image-size`** (deliberate): a script cannot write 10.0 apart from 10, so a whole number below 100 is a ratio of the frame's size, as Emacs reads a float, and one of 100 or more a limit in pixels.
- **Failed images** (not yet): an image that could not be loaded is not tried again at each redisplay, as Emacs tries it, until `image-flush` or `clear-image-cache`.
- **`image-mode`** (not yet) shows the image shrunk to fit and has `+`, `-`, `r`, `h`, `v` and `q`, but none of image-mode.el's other commands: no `C-c C-c` to see the bytes, no scrolling across a large image, no next and previous file, no animation, no fitting to the window's height or width on demand. The file's bytes are hidden behind the image with an `invisible` property, where Emacs's display property covers them. The image commands change an image at once, where Emacs waits for 0.3 seconds of idle time to batch them.
- **Display tables** (not yet): only the selective-display slot of `buffer-display-table` and `standard-display-table` is drawn, the string hidden text with an ellipsis shows as, and it holds a string, its faces as text properties, where Emacs's holds a vector of glyphs; the characters' own entries are not used.
- **Spell checking** (deliberate and not yet): Naming a combination of Hunspell dictionaries, as `en_US,sv_SE`, in `ispell-dictionary`, `ispell-local-dictionary` or `ispell-change-dictionary` makes it as `ispell-hunspell-add-multi-dic` would, where Emacs signals that the dictionary is undefined until that is called, and `ispell-hunspell-add-multi-dic` learns the checker first, as Emacs asks its caller to. `R` and `ispell-query-replace-choices` query-replace in a recursive edit, so the mode line shows brackets meanwhile. `?` with `ispell-help-in-bufferp` `electric` shows the help until a key is typed rather than in electric help mode, and `C-z` runs what `C-z` is bound to globally. The highlight of the misspelling is always an overlay, whatever the terminal (`ispell-highlight-p` `block`), and the other occurrences are highlighted in the window, as `ispell-lazy-highlight` does, but at once. `ispell-message` and the Spell menu are not there, as E8 has no mail mode or menu bar, nor `ispell-buffer-with-debug`'s debugging output. `C-c $` chooses a correction with the minibuffer, not a popup menu, and words typed with a self-inserting command are checked after `flyspell-delay` seconds idle by a timer rather than `sit-for`. In tree-sitter modes, whose faces are not text properties, `flyspell-prog-mode` checks words that the syntax table puts in comments and strings. Flyspell does not change abbrevs (`flyspell-abbrev-p`).
- **org-agenda** (not yet): `*Agenda Commands*` lists Org's views, but only `a`, `t`, `m`, `M`, `s`, `S` and `/` run; the others say E8 does not have them yet, and there are no custom agenda commands. The search view does not search the agenda files' archives when `org-agenda-text-search-extra-files` starts with `agenda-archives`, its whole words take `'` and `` ` `` as Org mode's syntax table does rather than as punctuation, and `[`, `]`, `{` and `}` in the week agenda signal rather than showing inactive timestamps too. The tags view's `Match:` prompt completes the tags of the buffer it was called from, not those of every agenda file, and `org-agenda-skip-function` is not read. A file in `org-agenda-files` that does not exist is visited as a new, empty one, where Org asks whether to remove it from the list.
- **org-capture** (not yet): a table line is aligned when the capture is finished, but a table's formulas are not fixed or recalculated, as E8's tables have none yet; a table line template with a line not starting with a bar becomes `| Bad template |` on a line of its own, where Org's runs into the line after it, and an item prepended to an indented list is indented as the list is (deliberate), where Org leaves it at the margin and the list's items become its children; Org captures in an indirect buffer and puts the target's narrowing back after it, where E8 captures in the target's buffer, narrowed, and leaves it widened; `%a` is the link `org-store-link` makes, so a buffer in another mode, as Info or mail, which E8 cannot link to yet, gives none; `%(sexp)` is left as it is, as E8 has no Lisp to run; `%x`, `%^C` and `%^L` offer the macOS app's selection too, where Org reads only X's and Windows' selections, so on a Mac never offers one; `%^{PROP}p` takes a property's allowed values from the target's headings, not from `org-global-properties` or `#+PROPERTY:` lines, and the template is filled in a buffer that does not take the target's `org-` variables; `C-c C-w` with `:kill-buffer` kills the target's buffer only if the capture visited it (deliberate), where Org's kills it even if it was open before; capturing from the agenda does not take the date at point (`org-capture-use-agenda-date`); and from code, `org-capture` takes only the prefix argument, not a template's keys, which `org--capture-with` takes.
- **org-clock** (not yet): there is no resolving of idle time or dangling clocks, `org-clock-display` leaves a heading with no title without its time where Org signals, and sums headings nested 60 levels deep where Org's table of levels runs out, `C-u C-u C-u C-c C-x C-i` and `C-u C-u C-c C-x C-x` do not start from the last clock-out time (`org-clock-continuously`), nor `C-u C-u C-u C-c C-x C-x` ask for a TODO state; `org-show-notification-handler` is called when it is a function but not run as a program when it is a string, other notices go to the echo area rather than the desktop's, and `org-clock-sound` is not played; the clock in the mode line has no menu or mouse bindings; a task's line in `*Clock Task Select*` shows its links as written, where Org's shows their descriptions; and `CLOCK_MODELINE_TOTAL` is inherited only when `org-use-property-inheritance` is t. `org-clock-ask-before-exiting` is read as E8 exits, where Org's takes effect only when customize sets it, adding or removing `org-clock-kill-emacs-query`. A clock table's `:formula` or an old table's `#+TBLFM:` line is written below the table but not computed, as E8's tables have no formulas yet. A `:formatter` or an `org-dblock-write:NAME` function gets the parameters as a list, keyword after value, and a clock table's data with each heading's properties as two-element lists, where Org's are dotted pairs; `org-dynamic-block-alist` is not a variable, but `org-dynamic-block-define` adds to what `C-c C-x x` offers.
- **Org filling** (not yet): Auto Fill and `M-q` (`org-fill-paragraph`) fill as Org does, though a source block in a language whose comments start lines, as Python's, is filled without `fill-comment-paragraph`, which E8's `fill-paragraph` lacks, so a comment's lines are joined as text; and a list item's text lines up one column after its bullet, without `org-list-item-body-column`'s handling of description items (`::`) or `org-list-two-spaces-after-bullet-regexp`.
- **`completing-read-multiple`** (not yet): the answer at point ends at the next separator, where crm's completion boundaries run to the end of the input; with a match required, `C-j` in icomplete and the other commands that test the input as Emacs's `test-completion` does need every answer to match, where Emacs's look only at the last; TAB's messages look at the whole input; the keymaps `crm-local-completion-map` and `crm-local-must-match-map` are not there, the usual minibuffer maps working on the answer at point; and the `completing-read-multiple` function takes no PREDICATE.
- **Org tags** (deliberate): `!` in fast tag selection makes Org's groups t when it turns them on, where there were none or after turning them off, and Org then signals `wrong-type-argument` at the next tag, while E8 goes on as if there were none. A `#+SETUPFILE:` that is a URL is not fetched. Setup files' keywords count for TODO states, tags, `#+STARTUP:`, `#+FILETAGS:`, `#+ARCHIVE:` and source blocks' `header-args`, but not yet for `#+PROPERTY:` in `org-entry-get`, `#+CATEGORY:` or `#+TITLE:`; and of what Org reads when Org mode starts, E8 keeps only the TODO states and TAGS lines so, reading `org-tag-alist`, `#+FILETAGS:`, `#+ARCHIVE:` and `#+CATEGORY:` as they are now.
- **Org properties from keywords**: `#+PROPERTY:` lines are read as the buffer is now, where Org reads them into `org-keyword-properties` when Org mode starts (or on `C-c C-c` on a keyword), so a line typed since counts at once in E8; a `#+SETUPFILE:`'s `#+PROPERTY:` lines count for source blocks' `header-args` but not for `org-entry-get`.
- **Org speed commands** (not yet): the key for `org-columns` says E8 does not have that command yet; `org-speed-commands` entries are [key, command] or [key, [function, ...arguments]], not Lisp forms.
- **Org sparse trees** (not yet): `org-agenda-tags-todo-honor-ignore-options` is not read, as the agenda has no `org-agenda-todo-ignore-` options yet; `org-occur-link-in-agenda-files` is not there yet; and a regexp that matches the empty string at point, as `^` does, goes on from the next character (deliberate), where Org's `org-occur` finds it there again for ever.

## Bidirectional text

E8 reorders text as Emacs 30.2 does, and `tests/emacs/bidi/` compares the two on 281 lines ([ADR 0047](adr/0047-bidirectional-text.md)). Where they differ:

- **Arabic in the GUI** (not yet): letters do not join, as each letter of a right-to-left script is drawn on its own, spaced to its column, so egui's shaper cannot turn the core's visual order around again. On a terminal Emacs does not join them either.
- **Directional controls in the GUI** (not yet): LRM, RLE, LRI and the others show as a space a column wide, as on a terminal, where Emacs's graphical frames show a thin space a pixel wide.
- **Line numbers** (not yet) stay left of a right-to-left row, where Emacs puts them on its right.
- **Strings in bidirectional lines** (not yet): a `(space ...)` display spec is reordered as an object, where bidi.c treats it as a paragraph separator; a display string in several faces is reordered a face at a time; and a line an overlay string with a newline breaks is not reordered.
- **Embeddings inside isolates** (not yet): a PDF that ends an embedding inside an isolate can take the level outside the embedding where bidi.c gives it the level inside, which moves where it shows.
- **The Arabic letter mark**, U+061C (not yet), shows as a space, where Emacs on a terminal shows it as itself.
- **`move-point-visually`** (not yet): on a truncated right-to-left line, and from inside text a display string covers, Emacs lays the line out afresh and lands elsewhere than what it shows suggests; E8 moves by what shows. At the end of the buffer on a wrapped line, Emacs can signal end-of-buffer where E8 stays.
- **A truncated right-to-left line** (not yet) is not scrolled sideways, by redisplay to keep point in view or by `set-window-hscroll`, as left-to-right ones are; its start shows at the right edge.
- **Lines continued with mixed directions** (unverified): moving by screen lines over a line whose rows hold characters from both ends of a run, as visual-order breaking can make, is not compared with Emacs.

- **Processes' odds** ([ADR 0086](adr/0086-the-odds-of-processes-buffer-text-and-windows.md)): E8 has no Lisp threads, so `process-thread` gives nil, where Emacs gives the thread that made the process, and `set-process-thread` takes only nil. `interrupt-process-functions` and `signal-process-functions` are not there; `internal-default-interrupt-process` and `internal-default-signal-process` are, and take a process's name and a signal's name as strings too. `internal-default-signal-process` gives -1 for a process that has ended without signalling the id it had, which may be another's by now. A serial port with no `:coding` reads and writes bytes as `no-conversion`, where Emacs reports `(nil . nil)`; `set-process-filter` and `set-process-sentinel` do not add to a serial or network process's contact, and a deleted serial process's contact is nil, where Emacs keeps its plist; `process-command` of a stopped serial port is nil, where Emacs gives t. `stop-process` and `continue-process` stop reading a serial port, connection, server or pipe process and signal a program, as in Emacs; a stopped server still takes connections. `:nodelay` is unsupported, as in Emacs 30.2's table though `make-network-process` documents it.
- **SQLite** ([ADR 0087](adr/0087-sqlite-as-emacs-has-it.md)): a database or set not closed or finalized stays open until E8 exits, where Emacs's garbage collector frees one nothing refers to. A string bound to `?` is UTF-8 unless its `coding-system` property is `binary`, which makes it a blob; another coding is not applied. Blobs come back as strings of characters U+0000 to U+00FF. On the web there is no SQLite.
- **Compositions** ([ADR 0092](adr/0092-compositions-as-emacs-has-them.md)): characters composed relative to each other, which Emacs draws on top of each other, are drawn as the first of them, and composition rules are not laid out. Automatic composition, which joins characters as a font's shaping says, does nothing: `find-composition` finds only `composition` properties, and `composition-get-gstring` gives each character a glyph of its own. A composition's modification function is kept but not called when its text changes, and `prettify-symbols-unprettify-at-point` is not looked at.
- **The C core's last odds** ([ADR 0093](adr/0093-the-c-cores-last-odds.md)): `event-convert-list` gives a key's description, as `"C-a"` or `"<down-mouse-1>"`, where Emacs gives a character's number, as E8's events are keys written as strings. `open-termscript` writes no file, and `tty--set-output-buffer-size` is kept but changes nothing, as E8's terminal writes each frame whole. `get-internal-run-time` gives seconds as a number rather than a Lisp time.
- **Defined coding systems** ([ADR 0094](adr/0094-defining-coding-systems.md)): a coding a script defines with an ISO 2022, Shift_JIS, Big5, emacs-mule or CCL type is written through its `:charset-list` as a charset coding is, without designations, escape sequences or a CCL program. Translation tables and post-read and pre-write conversions are kept on its plist but not applied. Definitions and aliases belong to the thread that made them, the editor's, rather than to the whole program.
- **Defined charsets** ([ADR 0095](adr/0095-defining-charsets.md)): a charset's `:map` file is not read, so one defined only by a map holds no characters. ISO 2022's final bytes start as Emacs's for E8's own charsets, which are fewer than Emacs's, so `get-unused-iso-final-char` can give a final Emacs's own charsets take, such as `0`, which is `chinese-sisheng`'s. Definitions and aliases belong to the editor's thread.
- **Deactivating the region** (not yet): E8 deactivates the region of each buffer a command changed when that command ends, a command called from code included, where Emacs reads `deactivate-mark`, buffer-local once set, only when a command loop's command returns, and resets it before each. So a command that edits or kills through other commands and then fails, as Org's `C-c C-x A` over a region signalling End of buffer does, leaves E8's region gone and Emacs's active; `e8.letBind({"deactivate-mark": false}, ...)` around such a call keeps it, as in Emacs.
- **The mark's marker** ([ADR 0096](adr/0096-the-mark-as-a-marker.md)): `mark-marker` stands for the mark, which E8 keeps as a position, so `set-marker` cannot point it into another buffer, as Emacs lets it do.
- **The macOS display's functions** ([ADR 0097](adr/0097-the-macos-displays-functions.md)): `ns-get-resource` gives only what `ns-set-resource` set this session, not macOS's defaults database. `ns-perform-service` and `ns-begin-drag` do nothing, and `ns-read-file-name` reads in the minibuffer rather than a file panel. PRIMARY and SECONDARY are the editor's own, not pasteboards other programs can read.
- **fns.c's strings** ([ADR 0098](adr/0098-fns-strings-and-buffers.md)): E8's strings do not say whether they are unibyte, so base64 takes a character from U+0080 to U+00FF as that byte, where Emacs signals for one in a multibyte string. `string-collate-lessp` compares code points whatever the locale, and `locale-info` gives English names for days and months.
- **Time** ([ADR 0099](adr/0099-time-as-emacs-has-it.md)): `current-time`, `encode-time`, `time-add` and their kin give seconds since the epoch as a number, where Emacs gives `(HIGH LOW USEC PSEC)` or `(TICKS . HZ)`; they take those forms too, a two-element list being `(HIGH LOW)` unless its second number is too large to be one. `format-time-string` names days and months in English, as in the C locale. On the web, which has no zone files, a named zone is UTC.
- **JSON** ([ADR 0100](adr/0100-json-as-emacs-has-it.md)): `jsonParseString` and its kin take their options as an object (`{ objectType: "alist" }`) rather than keyword arguments, and give objects as JavaScript objects where Emacs gives hash tables. `json-serialize` gives text, not a unibyte string of UTF-8. Integers past 2^53 lose precision, as E8's numbers are doubles.
- **Variables and symbols** ([ADR 0101](adr/0101-variables-and-symbols-as-emacs-has-them.md)): `commandp` takes a string as a command's name, as E8's names are strings, not as a keyboard macro. `makunbound` of a global variable forgets its documentation with its value. An error in a variable watcher is logged, not signalled, and a watcher's own changes call no watchers.
- **The printer and the runtime's odds** ([ADR 0102](adr/0102-the-printer-and-the-runtimes-odds.md)): `multibyte-string-p` and `string-bytes` take a character from U+0080 to U+00FF as multibyte, as E8's strings do not say they are unibyte; a raw byte counts as one byte. `random` gives other numbers than Emacs's for the same string seed.
- **Arithmetic** ([ADR 0103](adr/0103-lisps-arithmetic-and-memory.md)): E8's numbers are doubles, so `float` gives the number it is given and `round`, `floor` and the rest give whole doubles, not integers of their own type, and lose exactness past 2^53. `memory-use-counts` gives zeros, as the script engine keeps its own counts.
- **Running a buffer** ([ADR 0104](adr/0104-running-a-buffers-typescript.md)): `eval-buffer` and `eval-region` run TypeScript, a buffer that imports as a module from a file of its own, and take none of Emacs's arguments for printing results or reading forms.
- **fontset-info** ([ADR 0105](adr/0105-fontset-info.md)): each font's list holds the font alone, with no opened fonts after it, as E8's front ends do not draw with fontsets.
- **The last odds** ([ADR 0088](adr/0088-the-last-odds-frames-file-notifications-and-descriptions.md)): file notifications come from kqueue, read every 50 ms on the editor's thread while anything is watched, so an event can come up to 50 ms late; on Linux and the web there is no backend, and watching signals "File watching is not available" where Emacs would use inotify. kqueue's and file-notify's actions are strings, as E8 gives Lisp's symbols, and filenotify.ts has no remote watches. A callback's error is shown as "Error in file notification callback: ...". The ns frame primitives answer wherever E8 draws in a window, from what the front end writes, with alists as `[name, value]` pairs: `ns-frame-geometry` gives `tab-bar-size` too, the menu bar as drawn inside the frame, no tool bar and no internal border, and a border and title bar worked out from the outer and native sizes. Frames' stacking order is the editor's own, which the GUI does not follow when frames are restacked or lowered. E8 makes no switch-frame events, so `handle-switch-frame` is a function rather than a binding; `x-create-frame` takes none of the window system's special parameters, and `make-frame` does not go through `frame-creation-function`. `send-string-to-terminal` on a terminal is written before the next frame is drawn. `describe-vector` merges a char-table's ranges by `eq` values as `map-char-table` gives them.
- **Buffer text's odds** ([ADR 0086](adr/0086-the-odds-of-processes-buffer-text-and-windows.md)): E8's buffers keep their text in a rope, so `gap-position` gives the buffer's end and `gap-size` 0. `buffer-swap-text` shows both buffers' windows from their starts, as Emacs's does, with their point the buffer's where Emacs puts it at the start, and starts tree-sitter parsers on both again. `internal--set-buffer-modified-tick` changes the tick Lisp sees, `buffer-modified-tick`, and not the one the editor's own caches follow. `translate-region-internal` takes a table's characters, not the strings or vectors a char-table may give for several. Labeled restrictions (`with-restriction` with a label) are not set aside while a window is drawn, as Emacs's `reset_outermost_restrictions` does, so a window shows a buffer as narrowed as the code running in it left it.

## Windows and frames

- **Frames' display** (not yet): `window-system` is `ns` for the window on macOS and `x` elsewhere, as packages test it, though E8 draws with egui, not Cocoa or X; a frame is never a child frame, so `frame-parent` is nil; `lower-frame` is missing; and hiding, iconifying and raising a frame (`make-frame-invisible`, `iconify-frame`, `raise-frame`) are its `visibility` parameter and a request the GUI follows, which a terminal ignores. `select-window` with NORECORD, as `with-selected-window` uses it, leaves the buffer list alone but still counts the window as used.
- **Horizontal scrolling** ([ADR 0071](adr/0071-scrolling-as-emacs-has-it.md)): `scroll-left` and `scroll-right` set the least scroll when run by keys and never from code, having no SET-MINIMUM argument (not yet). E8's numbers do not tell an integer from a float, so `hscroll-step` is a fraction of the window only when it is not a whole number: 1.0 scrolls one column, where Emacs scrolls by the window's width (not yet). The mouse wheel does not scroll sideways, as `mouse-wheel-tilt-scroll`, off by default in Emacs, would (not yet). A scroll a command set lasts until point moves other than by a command that scrolls vertically, which E8 recognises by name where Emacs's window_scroll moves its record of point; and text inserted before point counts as point moving, where Emacs's record is a marker (not yet).
- **Screen lines** ([ADR 0071](adr/0071-scrolling-as-emacs-has-it.md), not yet): `window-line-height` and `window-lines-pixel-dimensions` answer from the window's rows laid out afresh, never nil, where Emacs answers nil until redisplay has drawn the window. `window-lines-pixel-dimensions` gives each row's text width on a terminal too, as Emacs's graphical frames do, where Emacs's terminal gives a line's last row the window's whole width and a continued row its width less the `\`. `vertical-motion` ignores CUR-COL, which only spares Emacs a scan. `compute-motion` follows indent.c's loop and skips invisible text, but counts no overlay strings and no compositions; its numbers match batch Emacs's, where an interactive Emacs 30 gives others for text after a newline. `window-lines-pixel-dimensions` without BODY leaves out a header line, which Emacs counts as its first row. `window-scroll-functions` run at the end of redisplay, from a marker at each window's start, where Emacs runs them as it picks a new start. `force-window-update` does nothing, E8 drawing every window afresh. A window's vertical scroll (`window-vscroll`) lasts while it starts at the same place in the text, as Emacs keeps it until redisplay picks a new start, but in the selected window a line inserted above its start moves the start, which ends it. A scroll of more than a row, which only a script can set, leaves rows scrolled wholly out of sight counted as visible. PRESERVE-VSCROLL-P is accepted and ignored, as E8's minibuffer never freezes a window's start.
- **The user and the system** ([ADR 0073](adr/0073-the-user-and-the-system-as-emacs-has-them.md)): `daemonp` is always nil, as E8 has no daemon (deliberate). `suspend-emacs` stops the terminal as Emacs does but ignores STUFFSTRING, and in a window, which has no shell to continue it, it is an error; `C-z` iconifies a window as Emacs's `suspend-frame` does (not yet). On the web there is one user, `user`, with ids of 0 (deliberate). While an agent acts, `suspend-emacs` asks first, as stopping the editor stops the agent's requests too (deliberate).
- **Window starts** (not yet): a window always starts at the start of a line. So in the terminal, `C-v` over continued lines scrolls by lines of text rather than screen rows ([ADR 0029](adr/0029-redisplay-beyond-rows.md)), and an image taller than the window cannot be scrolled through part way, as Emacs's `vscroll` does.
- **`posn-at-point`'s y** (not yet) is the top of the row, where Emacs gives the top of the glyph: below it for text beside a taller image, by the row's ascent less the font's. Emacs gives the row's top for some characters before or just after an image too.
- **Quitting a window and window states** (not yet): window.el's `quit-restore-window`, `quit-window` with `quit-window-hook`, `display-buffer-record-window`'s quit-restore parameter as Emacs 30 writes it (the kinds as symbols, buffers as objects, and for a reused window its previous buffer, start, point as a marker and height or width), `window--delete` with `frame-auto-hide-function` (`iconify-frame` by default, or a frame's `auto-hide-function` parameter), `window-state-get`, `window-state-put`, `window-state-buffers`, `window-swap-states`, `window-persistent-parameters` and `window-restore-killed-buffer-windows` are ported ([ADR 0069](adr/0069-windows-as-emacs-has-them.md)). Emacs 30.2 has no `quit-restore-prev` parameter, which came later, so neither has E8. A command and a function cannot share a name in E8, so `quit-window` and `window-swap-states` as commands take only what they read interactively: code passes a window to window.ts's `quitWindow` and windows and a size to `windowSwapStates`. A state is Lisp data in E8's arrays, so a pair `(KEY . VALUE)` prints as `(KEY VALUE)`: Emacs's printed states read in E8, but E8's do not read back as the same data in Emacs; positions count from 0, so a state Emacs wrote is one character out. A state has no horizontal or vertical scroll, scroll bars or fringes to restore, as E8's windows have none of their own; its windows' previous buffers keep positions, not markers, and the frame's root window is never `last`, as the minibuffer's window follows it in Emacs. `window--state-put-2` puts start and point without `noforce`, so a start E8 cannot show moves to its line's start.
- **The buffer list** (not yet): frames have no buffer lists of their own, and a buffer made after another was buried comes before it, where Emacs puts it after. `previous-buffer`'s skip options (`switch-to-prev-buffer-skip`, `switch-to-visible-buffer`) are not there.
- **The title bar** (deliberate): on macOS a window's title bar is transparent, taking the theme's background, and the window looks dark or light as that background is, as Emacs's frames do with the `ns-transparent-titlebar` and `ns-appearance` parameters set. Emacs shows the system's title bar unless they are; E8 has no frame parameters to turn it back. Full screen, the frame takes the whole screen.
- **The lattice at startup** (deliberate, [ADR 0109](adr/0109-the-lattice-at-startup.md)): the GUI's window opens on the buffer E8 would show, with E8's lattice drawn faintly behind it for a few seconds, where Emacs shows its splash screen, `*GNU Emacs*`. There is no splash screen; `inhibit-startup-screen` (and `inhibit-splash-screen`, `inhibit-startup-message`) set to t turns the lattice off, as does `e8-startup-lattice` set to nil.
- **Window sizes** (not yet): windows are sized as window.c sizes them, in the front end's units, cells on a terminal and points in the GUI, with window.c's new sizes applied together by `window-resize-apply` ([ADR 0069](adr/0069-windows-as-emacs-has-them.md)). A window's total lines and columns are worked out from its size in units, so `window-resize-apply-total` has nothing to do, and `window-new-total` is only kept. A window's normal size across its parent's combination is always 1.0, so a new normal size across one is not kept. window.el's resizing is ported, from `window-total-size` to `minimize-window`: `window-resize`, `window-resizable`, `window-min-delta` and `window-max-delta`, preserved sizes and `window-size-fixed`, `adjust-window-trailing-edge`, `enlarge-window` and its kin, `maximize-window` and `minimize-window`. Not there: resizing the minibuffer's window through them (`window--resize-mini-window` does nothing, as E8's minibuffer window sizes itself), resizing the root window as a frame is resized (`window--resize-root-window`, `frame-resize-pixelwise`), and scroll bars and right and bottom dividers, which count as nothing in a window's least size. Balancing and fitting are ported too: `balance-windows`, `balance-windows-area`, `count-screen-lines`, `window-buffer-height`, `fit-window-to-buffer` with all its arguments and `fit-window-to-buffer-horizontally`, and `shrink-window-if-larger-than-buffer`. A command and a function cannot share a name in E8, so `balance-windows` and `shrink-window-if-larger-than-buffer` as commands take no argument: code passes a window or frame to window.ts's `balanceWindows` and `shrinkWindowIfLargerThanBuffer`, and `fit-window-to-buffer` is a function, not a command. `fit-window-to-buffer` leaves a frame's only window as it is, as Emacs does with `fit-frame-to-buffer` nil, as E8 does not size frames to their buffers; fitting a width measures the lines from the window's start unwrapped, and `count-screen-lines` counts rows from the text's height in the default line height, a buffer no window shows unwrapped. The sizes `display-buffer` gives windows from numbers and fractions are still E8's own, taking from one neighbour. `enlarge-window` and `shrink-window` take only DELTA, the prefix argument, as commands: code resizes horizontally with window.ts's `enlargeWindow(delta, true)` and `shrinkWindow`. Splitting a window and deleting the others are window.el's on the selected frame only; on another frame `split-window` signals and `delete-other-windows` deletes the other windows one by one. The quit-restore parameter keeps the previous buffer's point as a position, where Emacs keeps a marker; quitting takes where the window was in that buffer from its previous buffers, which follow edits as the marker would. On a terminal, a frame made for a buffer is iconified by `frame-auto-hide-function` when quit, which a terminal ignores, as Emacs on a tty does.
- **Splitting and deleting windows** (not yet): window.el's `split-window`, with SIZE, SIDE and PIXELWISE, `window-combination-resize` (t, `side` and `atom`), `window-combination-limit` and the `split-window` parameter, `split-window-no-error`, `split-window-below` with `split-window-keep-point`, `split-window-right`, `split-root-window-below` and `-right`, `delete-window` with `delete-window-choose-selected` and the `delete-window` parameter, `window-deletable-p`, `delete-other-windows` with the `delete-other-windows` and `no-delete-other-windows` parameters, `delete-other-windows-vertically`, `one-window-p`, `other-window` with the `other-window` and `no-other-window` parameters, `delete-windows-on`, `window-main-window`, atomic windows (`window-atom-root`, `window-make-atom`, `display-buffer-in-atom-window`) and the checks of atomic and side windows are ported, on window.c's `split-window-internal`, `delete-window-internal` and `delete-other-windows-internal` ([ADR 0069](adr/0069-windows-as-emacs-has-them.md)). A command and a function cannot share a name in E8, so `delete-window`, `delete-other-windows`, `other-window`, `split-window-below`, `split-window-right` and `delete-windows-on` as commands take only what they read interactively: code passes a window to window.ts's `deleteWindow`, `deleteOtherWindows`, `splitWindowBelow` and `splitWindowRight`, ALL-FRAMES to `otherWindow`, and a frame to `deleteWindowsOn`. The core splits and deletes this way only the selected frame's windows: `delete-window` on another frame's window gives its space to a sibling, as the core's `e8.deleteWindow` does, which packages still call, as they do `e8.splitWindow`, E8's own. `window-toggle-side-windows` keeps the frame's state in its `window-state` parameter and puts it back with `window-state-put`, as window.el does, but does not reverse side windows, as `window-sides-reversed` is not there. `window-deletable-p` takes no frame to hold another's minibuffer, as E8 has one for all frames; `kill-buffer-and-window` deletes the window before killing the buffer, not from `kill-buffer-hook`; and splitting runs no `window-scroll-functions`. In the GUI, whose mode line and the room above the text are taller than a line, the core's `e8.splitWindow` and `e8.splitRootWindow`, which packages call, grow a window given two lines or more, or two columns, to hold a line of text, where Emacs would make it the size given; fewer is still too small, as in Emacs.
- **`display-buffer`** (not yet): the actions, action functions and alist entries are window.el's ([ADR 0069](adr/0069-windows-as-emacs-has-them.md)), with Lisp's data as arrays: an alist entry `(KEY . VALUE)` is `[KEY, VALUE]`, an action `(FUNCTIONS . ALIST)` is `[FUNCTIONS, ...ALIST]`, and a `display-buffer-alist` entry is `[CONDITION, FUNCTIONS, ...ALIST]`. Code passes an action to window.ts's `displayBuffer` and `popToBuffer`, as the `display-buffer` command takes only a prefix argument, and a `pop-to-buffer` that uses no window does not make the buffer current, as scripts have no `set-buffer`. Not there yet: `display-buffer-in-tab` and `display-buffer-in-new-tab`, `display-buffer-in-child-frame`, `window-sides-reversed`, and the frames `pop-up-frame-alist` describes. `display-buffer-at-bottom`, `display-buffer-in-direction` and `display-buffer-in-side-window` still take the live windows an internal window holds, such as the main window beside side windows, and split the smallest window holding them, a new major side window is split off at a quarter of the frame rather than fitted afterwards, and a new side slot shares the side evenly by resizing its windows. `display-buffer-override-next-command` adds no prefix to the echoed keys, as E8 has no `prefix-command-echo-keystrokes-functions`.
- **windmove and winner** (not yet): windmove.el and winner.el are ported, and preloaded rather than autoloaded. `windmove-mode`, on from the start in Emacs once windmove.el has loaded, turns on here when the `*-default-keybindings` first bind its keys. E8's keys have no super, hyper or alt modifier, so `windmove-swap-states-default-keybindings` binds nothing with its default `shift` `super`, and says so; the `*-default-keybindings` commands take no argument, code passing modifiers and a prefix to windmove.ts's `windmoveDefaultKeybindings` and its kin, and the `windmove-default-keybindings` options that bind keys when customized are not there. `windmove-display-new-frame` makes a frame without `pop-up-frame-parameters`. Winner takes a configuration after each command that changed the windows, as `window-configuration-change-hook` runs then, where Emacs takes it as it redisplays, so a resize alone is not recorded; it reads `winner-dont-bind-my-keys` as the mode turns on, not as winner.el loads, and keeps the minibuffer window's size as E8 does, not as the configuration had it. `winner-repeat-map` is there for when E8 has `repeat-mode`.
- **Window configurations** (not yet): a previous-buffer entry a window dropped after the configuration was saved comes back as it was then, not as a marker that followed edits.

## Files and the clipboard

- **Auto-revert and file notifications** (deliberate): Auto-Revert is told of changes by kqueue on macOS and the BSDs and inotify on Linux, as Emacs is, and looks every `auto-revert-interval` seconds as well unless `auto-revert-avoid-polling`. An inotify watch's descriptor is one number, the system's descriptor × 65536 + the watch's id, where Emacs gives `(DESCRIPTOR . ID)`, as E8 has no conses. There are no remote files, so `auto-revert-remote-files` changes nothing, and no version control, so a revert updates none ([ADR 0113](adr/0113-files-reverting-and-notifications.md)).
- **File primitives** ([ADR 0072](adr/0072-files-as-emacs-has-them.md), deliberate): times are milliseconds since 1970, as `e8.fileAttributes` gives them, not Lisp timestamps, so `visited-file-modtime` is a number, 0 when none is known and -1 for a file that did not exist, and a file last modified at exactly 1970's start reads as 0. ID-FORMAT is ignored, the attributes giving both ids and names, and `directory-files-and-attributes` gives each file's attributes as `e8.fileAttributes` does, an object rather than Emacs's list. E8 has no ACL or SELinux support, so `file-acl` and `file-selinux-context` answer as Emacs does without them. On the web, with no trash, `system-move-file-to-trash` deletes.
- **The clipboard** (not yet): X11's primary selection is not used, and the terminal does not write the clipboard ([ADR 0031](adr/0031-the-system-clipboard.md)).
- **Dired's guessed commands** (deliberate): `!` and `&` offer what `shell-command-guess` guesses as completions as well as on `M-n`, where Emacs's `read-shell-command` offers them on `M-n` only. Mailcap's entries are read without their `test=` conditions, and XDG's guess is the type's default application only, where Emacs's `xdg-mime-apps` lists every application for it ([ADR 0022](adr/0022-dired-and-projects.md)).
- **`describe-current-coding-system`** (deliberate) lists the coding systems detection tries in E8's order, which has no `emacs-mule`, ISO 2022 variants or CCL codings; the rest of what it shows is Emacs's ([ADR 0035](adr/0035-coding-systems-and-charsets.md), [ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **File name handlers** (not yet) are asked by the primitives that read and change files, as in Emacs: visiting, saving, the predicates, `expand-file-name`, `file-attributes`, `directory-files`, `copy-file`, `rename-file`, `copy-directory`, `delete-file`, `make-directory`, `delete-directory`, `make-symbolic-link`, `add-name-to-file`, file name completion and locking. Not yet by those TRAMP also handles that E8 does in its own code: the name functions (`file-name-directory`, `file-name-nondirectory`, `file-name-as-directory`, `directory-file-name`, `file-name-sans-versions`, `substitute-in-file-name`), `file-remote-p`, `file-local-copy`, the programs (`make-process`, `process-file`, `start-file-process`, `shell-command`), the file notifications, `load`, `insert-directory` and `set-visited-file-modtime`; E8 has no TRAMP to use them ([ADR 0113](adr/0113-files-reverting-and-notifications.md)).
- **A keymap's keys** (deliberate) are kept in order where Emacs keeps the newest binding first, so `map-keymap-internal` visits them, and `C-h b` lists the blocks under one prefix, in E8's order; the lines in each block are in Emacs's ([ADR 0082](adr/0082-keymaps-rest-as-emacs-has-them.md)).
- **`C-h b`'s sections** (not yet): E8 has no `local-function-key-map`, so `describe-buffer-bindings` writes no "Function key map translations" section, and it writes no "Overriding Bindings" either, as the modal commands that set an overriding map end before `C-h b` runs ([ADR 0082](adr/0082-keymaps-rest-as-emacs-has-them.md)).
- **A keymap's prompt** (not yet) is kept and given back by `keymap-prompt`, but reading a key in such a keymap shows no keyboard menu built from it, as Emacs's `menu-prompting` does ([ADR 0082](adr/0082-keymaps-rest-as-emacs-has-them.md)).
- **Flyspell while scrolling** (deliberate): `flyspell-deplacement-commands` holds `mwheel-scroll`, `scroll-up-line` and `scroll-down-line` beside `scroll-up` and `scroll-down`, so a word is not checked on every step of a wheel or trackpad scroll, which made scrolling a long file lag. Emacs's list predates `mwheel-scroll`, which calls `scroll-up` and `scroll-down` itself.
- **Flyspell does not wait for the checker** (deliberate): the word a command leaves, or one checked after `flyspell-delay`, is sent to the checker and marked when its answer comes, a few milliseconds later, rather than the command waiting for it, as Hunspell takes up to 50 ms over a word it does not know. What the checker said of a word is remembered until what it accepts changes, and more than 32 words not yet asked about, as `flyspell-buffer` checks, are shared out between the checker and up to three more started as it was, so `M-x list-processes` shows `ispell-helper` processes beside `ispell` ([ADR 0109](adr/0108-spell-checking-off-the-editor-thread.md)).
- **The display's size** (deliberate) is what the front end writes in: pixels in a window, characters on a terminal, as Emacs's `display-pixel-width` answers `frame-width` on one. Its size in millimetres is unknown, so `x-display-mm-width` is nil where Emacs's gives a number ([ADR 0081](adr/0081-the-display-as-emacs-asks-about-it.md)).
- **Monitors** (not yet): there is one, the window's own, as egui knows no others, so `display-monitor-attributes-list` has a single entry where Emacs lists every screen; its `workarea` is the whole monitor, as egui says nothing of the system's own bars, so a frame placed from it can land under the menu bar ([ADR 0081](adr/0081-the-display-as-emacs-asks-about-it.md)).
- **`ns-do-applescript`** (not yet) gives back what the script said as a string, where Emacs gives a number for a number and `t` for a bare result ([ADR 0081](adr/0081-the-display-as-emacs-asks-about-it.md)).
- **`x-open-connection`** (deliberate) is refused, with `x-close-connection` and `x-create-frame`: E8 draws through one front end, and `make-frame` makes a frame from the same parameters ([ADR 0081](adr/0081-the-display-as-emacs-asks-about-it.md)).
- **HTML parsed into a tree** (deliberate): E8 follows the HTML5 algorithm, as browsers do, where Emacs's libxml2 has its own recovery. So E8 puts a `tbody` around a table's rows, keeps the whitespace at the start of an element's content that libxml2 drops, and keeps an SVG attribute's case (`viewBox`, not `viewbox`); `head` and `body` match, as an empty one the page did not write is dropped ([ADR 0080](adr/0080-xml-and-html-as-emacs-parses-them.md)).
- **A document nested deeper than 256** (deliberate) gives the tree to that depth, as libxml2 parses HTML 256 deep ([ADR 0080](adr/0080-xml-and-html-as-emacs-parses-them.md)).
- **XML entities and CDATA** (not yet): E8 expands an entity the document declares, where Emacs leaves nil in its place, and refuses a document that declares an external entity, where Emacs parses it; CDATA joins the text around it, where Emacs keeps it apart ([ADR 0080](adr/0080-xml-and-html-as-emacs-parses-them.md)).
- **DISCARD-COMMENTS** (deliberate): `libxml-parse-html-region` and `libxml-parse-xml-region` drop every comment when it is given, as their docstrings say; Emacs 30.2's keep them ([ADR 0080](adr/0080-xml-and-html-as-emacs-parses-them.md)).
- **`current-idle-time`** (deliberate) gives the seconds idle as a number, the unit `run-with-idle-timer` takes, where Emacs gives a Lisp timestamp; E8 has no timestamps, and reports times as numbers everywhere ([ADR 0079](adr/0079-the-keyboards-odds-and-ends.md)).
- **The input modes** (deliberate) are state, not behaviour: `current-input-mode` says what E8 does — interrupt-driven, no flow control, the eighth bit as meta — and `set-input-mode` and its kin keep what they are given so a package can save and restore them, but nothing E8 does changes with them, the quit character included, which stays `C-g`. E8's front ends read the terminal themselves, in raw mode ([ADR 0079](adr/0079-the-keyboards-odds-and-ends.md)).
- **The dribble file** (deliberate) holds a plain character as itself and anything else in angle brackets, `<C-c>`, where Emacs writes a character's byte and an event's name ([ADR 0079](adr/0079-the-keyboards-odds-and-ends.md)).
- **`internal-handle-focus-in`** (not yet) selects the frame itself where Emacs makes a switch-frame event the command loop acts on later; E8 has no such event ([ADR 0079](adr/0079-the-keyboards-odds-and-ends.md)).
- **`send-string-to-terminal`** (deliberate) is not there: front ends draw from the frame description, and nothing writes to the terminal behind them ([ADR 0079](adr/0079-the-keyboards-odds-and-ends.md)).
- **A coding system's plist** (deliberate): `coding-system-plist` gives Emacs's properties, written from Emacs by `tests/emacs/coding-plists.el`; a `:charset-list` can name charsets of Emacs's that E8 has no table for, as `tis620-2533` and `gb18030-2-byte` ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **A function in a coding alist** (deliberate): E8 calls a lambda as well as a function's name, where Emacs calls only a name (`SYMBOLP`), since a value in E8 may be a function anywhere else ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **`coding-system-put`** (deliberate): `:mnemonic` changes the letter the mode line shows, as in Emacs; `:ascii-compatible-p` is kept but changes nothing, where Emacs takes ASCII-only text through a faster path for a coding that says it, which E8 decodes the same way either way ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **`define-coding-system-alias`** (deliberate) is not there: E8's coding systems are a static table ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **A charset's plist** (deliberate): `charset-plist` gives Emacs's docstring, short and long names, `:iso-final-char`, `:emacs-mule-id` and the name of its `:unify-map`, though E8 builds its charsets rather than loading maps, with what E8 works out, but not `:code-offset`, `:base` or `preferred-coding-system` ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **`encode-sjis-char` of half-width katakana** (deliberate) gives the one Shift JIS byte, 177 for `ｱ`; Emacs converts through JIS and gives 28847. ASCII and the two-byte codes agree ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **`charset-id-internal`** (deliberate) is a charset's place in E8's own table, which is not Emacs's numbering ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **Unicode property tables** (deliberate): `unicode-property-table-internal` gives a char-table for each property of `char-code-property-alist`, from Emacs's data written by `tests/emacs/unidata.el`; the `name` table holds the names Unicode gives one by one, not those made from the code, as CJK IDEOGRAPH-4E00 or a Hangul syllable's, which Emacs's table works out when asked and E8's `get-char-code-property` works out too ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **Defining a charset** (deliberate): `define-charset`, `define-charset-internal`, `iso-charset`, `declare-equiv-charset`, `get-unused-iso-final-char` and `map-charset-chars` are not there; E8's charsets are a fixed table naming the code points its coding systems convert ([ADR 0078](adr/0078-charsets-and-codings-as-emacs-has-them.md)).
- **Raw bytes** (deliberate): bytes that are no text in their coding are the characters U+10FF80 to U+10FFFF, where Emacs's are beyond Unicode at #x3FFF80 to #x3FFFFF. They show and are written back as in Emacs ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **Unibyte strings** (deliberate): scripts hold bytes as strings of characters U+0000 to U+00FF, as Emacs prints unibyte strings, and a string with other characters stands for its UTF-8. So inserting `encodeCodingString`'s result shows Latin-1 letters where Emacs's shows `\303\251` ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **The `charset` text property** (not yet): Emacs puts it on text decoded in a charset's coding and uses it when encoding again. E8 has none, so `iso-2022-7bit` chooses each character's set by the text's script: JIS X 0208 for text with kana, KS C 5601 with Hangul, else GB 2312, where Emacs writes kana alone in GB 2312's set ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **Japanese files without a cookie** (not yet): with the Japanese language environment (`C-x RET l`), Shift_JIS and EUC-JP files are found, as in Emacs; without it, E8 opens Shift_JIS as Latin-1, where Emacs's detection takes Shift_JIS when C1 control bytes rule Latin-1 out ([ADR 0035](adr/0035-coding-systems-and-charsets.md)).
- **Coding found by functions** (deliberate): `auto-coding-functions` are called before a file's text is read, with its name in `auto-coding-file-name` and its size, so a function has the name to go by but not the text; the XML and HTML declarations Emacs's own functions look for, E8 finds itself, so the variable starts with only editorconfig's function, which gives nothing unless `editorconfig-mode` is on.
- **Language environments** (not yet): `set-language-environment` and `C-h L` have Emacs's environments, written from Emacs by `tests/emacs/languages.el`, and set the coding systems, charsets and default input method as Emacs does, but E8 has no input methods, so `C-h L` lists none. Of the environments' setup functions E8 does Japanese's, which prefers UTF-8, and Catalan's middle dot; not the CJK ones' character widths, Thai's word mode, Korean's and Ethiopic's keys or Turkish's case table. The coding systems and charsets an environment names that E8 does not have are left out of what it sets and shows, and E8 does not set one from the locale at startup, keeping UTF-8.
- **Imenu** (not yet): the index is kept with markers until `*Rescan*`, as in Emacs, and `imenu-add-menubar-index` puts it on the menu bar, but M-x imenu always reads with completion, never from a popup menu (`imenu-use-popup-menu`), and `imenu-flatten`'s `annotation` and `group` act as `prefix`, as minibuffer completion here has no annotations or groups. An index function may give a JavaScript function as a pattern's regexp where Emacs takes a Lisp one, and match data is not kept around `imenu--generic-function` ([ADR 0039](adr/0039-imenu.md)).
- **Comint** (not yet) has no history expansion (`!!`, `!str`, `^old^new`, `comint-input-autoexpand`, `comint-c-a-p-replace-by-expanded-history`) and no pcomplete, so TAB in a shell completes file names, commands, environment variables and directory-stack references, but not a command's own arguments as `pcomplete/git` and its kin do. Completing a file name lists the names with their directory as typed, as E8's completion in a buffer takes a list of names rather than a table with boundaries, and `comint-unquote-function` and `comint-requote-function` are not there: backslashes and `$VAR` are taken out of the directory to read it, and a name's quoting put back with `comint-quote-filename`. With `comint-use-prompt-regexp`, `C-c C-n` and `C-c C-p` go to the lines `comint-prompt-regexp` matches, where Emacs moves by the paragraphs it starts, as E8's paragraph motion keeps to its default `paragraph-start` ([ADR 0038](adr/0038-comint-and-shell.md)).
- **Compilation output** (not yet): its ANSI escape sequences are taken out as it comes, where Emacs leaves them unless `ansi-color-compilation-filter` is on `compilation-filter-hook`, and `compilation-filter-start` is not set for that hook.
- **Pipe processes** (not yet): one given to a program as its standard error cannot be given to another, where Emacs lets several programs write to it ([ADR 0070](adr/0070-processes-as-emacs-has-them.md)).
- **`call-process-region`** (deliberate) sends its input on a pipe rather than through a temporary file, so no file name handler is asked about one. With DISPLAY, output goes into the buffer, and is shown, a whole line at a time as it comes, and in UTF-16 only at the end ([ADR 0112](adr/0112-the-environment-programs-run-in.md)).
- **`process-attributes`** (deliberate) gives times as seconds, `start` as seconds since 1970, rather than Lisp timestamps. On macOS it has Emacs's keys for E8's user's processes, but for another user's only those `proc_pidinfo` gives without privileges (euid, user, egid, group, comm, state, ppid and pgrp), where Emacs, reading them through sysctl, also has `start`, `etime`, `nice` and `tpgid`. On Linux it reads `/proc` as Emacs does, `ttname` only for pseudo-terminals and virtual consoles.
- **`process-running-child-p`** (deliberate) is t for a program on pipes, which has no terminal to ask, as Emacs's documentation says; Emacs on macOS answers 0 there.
- **`getenv-internal`** (deliberate) given a frame looks in `process-environment` only, as E8 has one terminal and frames have no `environment` parameter ([ADR 0112](adr/0112-the-environment-programs-run-in.md)).
- **Serial processes, datagrams, `set-network-process-option` and `process-thread`** are left out, as no package in the corpus needs them yet; scripts have no threads of their own for `process-thread` to name ([ADR 0070](adr/0070-processes-as-emacs-has-them.md)).
- **Network connections** (not yet): `open-network-stream` does no STARTTLS (`:type starttls`, or `network` with `:capability-command` and `:success`) and no `:type shell`, refusing them rather than connecting without encryption, and a connection with `:tls-parameters` connects before returning, `:nowait` or not ([ADR 0037](adr/0037-terminals-sockets-and-process-codings.md), [ADR 0112](adr/0112-the-environment-programs-run-in.md)).
- **What programs are given** (deliberate): TERM is "dumb" unless `process-environment` sets a TERM other than the one E8 was started with, and INSIDE_EMACS is "e8" if it is not set, where Emacs passes its own environment's TERM on and sets INSIDE_EMACS only in comint and compilation buffers; `exec-path` starts as PATH's directories without `exec-directory` after them, as E8 has no programs of its own to run ([ADR 0112](adr/0112-the-environment-programs-run-in.md)).
- **Connecting or listening** (deliberate) asks the agent's permission while it acts, as running a program does.
- **Changing a file's modes or times** (deliberate) asks the agent's permission while it acts, as writing files does; Emacs has no agent to ask.

## Invisible differences

Kept for completeness, as they cannot be seen:

- Show Paren mode's idle timer exists only while the mode is on.
- The standard case and category tables are made as char-tables only when code asks for them.
- An indirect buffer keeps a copy of its base's text, which the editor keeps the same after every change, where Emacs keeps one copy ([ADR 0034](adr/0034-buffer-and-text-property-primitives.md)).
- Fields compare `field` values with `equal`, where Emacs uses `eq`; only two distinct strings with the same text tell them apart.
- **Isearch** (not yet) has no scrolling while searching, character folding (`M-s '`), `M-TAB` completion from the search ring or `isearch-occur` and the highlighting commands under `M-s`, and no prefix arguments typed while searching (`isearch-allow-prefix`), so `C-u 2 C-s` there ends the search; its prompt shows no `isearch-fail` face on what fails to match, as E8's messages are plain text. In the minibuffer `M-e` opens, `M-p` starts from the newest search, where Emacs starts after the one `M-p` in the search brought. `isearch-lazy-count` counts every match in the buffer as each key is typed, where Emacs counts by a timer, so a very large buffer is slow to count, and it counts and highlights matches in folded text that cannot be opened, which Emacs leaves out ([ADR 0042](adr/0042-isearch-state-and-comint-history-search.md)).
- **Faces** (not yet) have no stipples. Double, dotted and dashed underlines draw as plain lines and raised or pressed boxes as plain boxes. An underline goes where the font puts it, at least a pixel below the baseline, as Emacs's does by default; `x-underline-at-descent-line` and `underline-minimum-offset` are not there to move it. The terminal draws no overline, box or wave, as Emacs on a terminal does not ([ADR 0044](adr/0044-faces-as-emacs-s.md)).
- **Fonts** (not yet): a face draws in any installed family it names, its regular weight only, one frame after it is first named ([ADR 0052](adr/0052-faces-in-installed-fonts.md)); the `default` face's family does not change the window's main font, and there is no `set-frame-font`. `list-fonts` and `x-list-fonts` offer each installed family in regular, bold, italic and bold italic without asking the system which styles exist, and font capabilities (`:otf`, scripts) are missing; `x-family-fonts` gives each family's four styles at point size 0, as for fonts that scale. egui keeps no ascent, so an open font's ascent and descent split its line four to one. A script cannot write a float such as `12.0`, so a size in points is `:point-size` ([ADR 0048](adr/0048-overlay-arrows-fringe-indicators-and-fonts.md)).
- **The C core's primitives by their names** ([ADR 0090](adr/0090-the-c-cores-primitives-by-their-names.md)): `format`'s `%s` of a whole number in floating point prints no point, `1` where Emacs prints `1.0`, as E8's numbers cannot tell them apart. `set-buffer-multibyte` only sets `enable-multibyte-characters`, as E8's buffers always hold characters. `key-description` reads a string as E8's description of keys where it reads as one, else as Lisp's string of characters. `make-keymap` makes a sparse keymap, as E8's keymaps all are. `interactive` and `mark-marker` are missing: commands declare their parameters their own way, and E8's mark is a position, not a marker.
- **xwidgets** ([ADR 0089](adr/0089-xwidgets-as-emacs-has-them.md)): web views are native views over the GUI's window, as on Emacs's macOS build, not drawn into the frame as on its GTK build: they draw above E8's own menus and tooltips, take keys and clicks natively once clicked, and one partly scrolled out of its window shows its page from the top of the part still in it. On Linux under Wayland a view opens in a window of its own, with a box of its size and title in the buffer. An xwidget shown in two windows shows its view in the first. `make-xwidget` signals on a terminal and the web, where an xwidget's display property shows its text; `xwidget-perform-lispy-event` only checks its xwidget, and cookie storage files are kept but not used where the web view keeps its own cookies. A script's result reaches its function with arrays as lists and objects as lists of `[key, value]` pairs, as Lisp's alists are, and a script with a function runs once the view's first page has loaded; a script of several statements gives its value through `eval`, or, where a page's Content Security Policy forbids that, only what it returns. `xwidget-webkit-load-html` takes no base URI, `make-xwidget`'s RELATED shares nothing, `load-committed` comes just before `load-finished` rather than when WebKit commits, `decide-policy` comes for every navigation, the first `about:blank` included, load progress is reported only when a page has finished, and a download's MIME type is empty: the view saves downloads in `~/Downloads` itself, where Emacs asks where, and `download-callback` only says where it went. Running a page's JavaScript and loading HTML ask the agent's permission as loading a URI does, as both can load any page. Views in frames other than the main window are drawn as boxes. URIs, titles and history are what the web view last reported, not asked of it at the time. On Linux under X11, a click back in E8's text may leave the keyboard with the page (not tried there), and under Wayland a view's window that is closed comes back only when its xwidget is shown again. xwidget.ts has no history buffer, edit mode, textarea editing or isearch of its own, `C-s` searching once.
- **Window display tables** ([ADR 0086](adr/0086-the-odds-of-processes-buffer-text-and-windows.md)): a window's display table, as `set-window-display-table` gives it, counts before the buffer's and the standard one for what E8 reads from display tables, the selective-display slot hidden text shows; split windows and window configurations do not carry it. `resize-mini-window-internal` sets the minibuffer window to the size `set-window-new-total` gave it, which redisplay sizes again as `resize-mini-windows` says.
- **Face and font internals** ([ADR 0085](adr/0085-face-and-font-internals-as-emacs-has-them.md)): a face has one definition for every frame, so Emacs's global face (FRAME t, which `internal-make-lisp-face` and `internal-lisp-face-p` use by default) and a frame's own are the same, and what one sets the other shows; `internal-merge-in-global-face` has nothing to merge, and `frame--face-hash-table` is a copy made when asked for, not the frame's own table. `reset` and `:ignore-defface` are taken as `unspecified`, where Emacs's `reset` takes the default face's value. Values Lisp tells apart by type and E8 by kind are accepted from scripts as strings where Emacs wants symbols (`:weight "bold"`), but a symbol where it wants a string still signals `stringp`. A pair Lisp writes as a cons is a two-element array: `internal-char-font`'s `[font, code]`, `x-load-color-file`'s `[name, rgb]`, a fontset's `[family, registry]` and a range `[from, to]`. E8's front ends give no glyph codes, so `internal-char-font` and `font-get-glyphs` give the character's own code, a glyph's bearings are 0 and its width, and `font-variation-glyphs` gives none; `font-shape-gstring` gives nil, as for a font that cannot shape. `font-match-p` does not check a spec's `:script`, `:lang` or `:otf`, and takes a size in points as that many pixels. Fontsets are kept and answered (`set-fontset-font`, `fontset-font`, `new-fontset`, `query-fontset`), but the front ends do not draw with them yet, and E8's default fontset starts with none of the fonts fontset.el gives Emacs's; `query-fontset` answers on a terminal, where Emacs says no window system is in use, and `fontset-info` is missing. A stipple of nil or given as a bitmap list is checked but not kept, so nil does not cancel an inherited stipple. `internal-char-font` gives the face's own font even where a fallback font draws the character, as E8's front ends do not say which font falls back. Sizes in points are pixels, as on Emacs's Mac frames, where a point is a pixel. E8 reads no X resources (`internal-face-x-get-resource` gives nil).
- **Fringes and margins** (not yet): no `overflow-newline-into-fringe` setting (the cursor at the end of a full line goes in the fringe regardless), no periodic bitmaps, and a top or bottom indicator taller than its row is not carried into the next. One bitmap shows per fringe, the overlay arrow's in place of the left one where Emacs draws it over. Fringes are always 8 points wide, and a defined bitmap's bits are points, so it draws small on a high-density display. The GUI's bell sounds only on macOS; elsewhere egui has no sound, so the frame flashes ([ADR 0045](adr/0045-margins-fringes-and-redisplay-primitives.md), [ADR 0048](adr/0048-overlay-arrows-fringe-indicators-and-fonts.md)).
- **Quitting** (not yet): `C-g` stops a running command at its next safe point, as in Emacs, and the window goes on drawing meanwhile ([ADR 0051](adr/0051-the-editor-thread.md)). Reading and writing files, decoding, `parse-partial-sexp` and sorting do not check for a quit yet. A script's columns after a loop's opening brace are off by the length of the check put there ([ADR 0049](adr/0049-quitting.md)).
- **Wrapping** (not yet): a display string standing for text is never split by wrapping, where Emacs continues it on the next line; a long message in the echo area wraps without the `\` a terminal shows at each break ([ADR 0029](adr/0029-redisplay-beyond-rows.md)).

## Packages and tests

- **News** (deliberate): the command is `view-e8-news`, with `view-emacs-news` another name for it, and E8 carries one NEWS file for every release rather than one for each major version; a release's heading is found by the number that ends it, as E8's name has a digit before it. `describe-package` lists only packages installed from repositories and those that ship with E8, says a built-in package's summary and description from the comment its file starts with, and has no Delete or Install buttons.
- **Installing packages** (not yet): only from git repositories, as package-vc does, with git on PATH; there are no archives, so no `list-packages` to browse, no `package-install` by name, and no tarball downloads. Upgrading a package takes effect when E8 next starts, as a module once imported is not imported again. Packages are installed in `repos/` beside `init.ts`, where Emacs's go in `elpa/` (deliberate: they are neither Emacs Lisp nor from an archive). There are no autoloads, so `package-vc.ts` is preloaded for its commands ([ADR 0059](adr/0059-packages-are-git-repositories.md)).
- **ERT** (deliberate): `should` is given a value, or a function whose source it shows, not a form, so `shouldEqual` stands for `(should (equal A B))` to show both values; there are no `ert-explain` explanations, no `M-x ert` results buffer commands, and test bodies run without awaiting.
- **acp** (not yet): the client follows acp.el 0.18.2, but its traffic buffer is a line for each message, without acp-traffic.el's browser, and what the agent writes to standard error reaches the error handlers when its output, its end or a quarter-second timer looks at its stderr buffer, where Emacs's after-change hook sees it at once. The process group is signalled only while the agent runs, so children it left behind after exiting are not killed at shutdown. Requests from TRAMP directories are not supported ([ADR 0061](adr/0061-agents-over-acp.md)).
- **agent-shell** (not yet): Claude Code's adapter (`claude-agent-acp`, as of 2026-11-06) reads and writes files with its own tools and asks under Claude Code's own permission settings, so with it E8's buffer-backed `fs/` methods and permission questions go unused, unless it uses E8's own tools, which it is given and which ask ([ADR 0062](adr/0062-agents-through-e8-mcp-ask-first.md)); a buffer with no unsaved changes visiting a file a tool call touched is reverted when the call completes, one with changes is left alone. E8's own Org buffer rather than agent-shell's shell-maker one, after its design, drawn as a chat over its Org text by display properties as agent-shell's chat mode draws over comint's, the thinking and tool calls between what the agent says in an Org `:ACTIVITY:` drawer that shows as one line, where agent-shell groups them with ▶ and ▼ and its own folding; the marks are ●, ◔, × and ◇ rather than ✓, ✗ and ✶, which egui's own font lacks, a group's line keeps to the past tense with its worst status's mark where agent-shell's says "Running" while it runs, the spinner is ASCII at the buffer's end and on the mode line rather than in an SVG header line, which E8 cannot draw, and the context's share is coloured but not a bar; the agent's Markdown converted to Org text rather than shown through overlays as agent-shell's markdown-overlays does; the conversation a transcript as agent-shell's and comint's, the agent's turns and the requests sent read-only and never undone, since an ACP session can take nothing back, while gptel's document model, where the buffer is the conversation and editing it changes what the model sees next, waits for the Messages API backend of one M-x agent: no terminals for the agent, no viewport or prompt queue, no images or files attached to a prompt; a resumed session is always replayed in full, every reply but the last folded, where agent-shell's `agent-shell-session-restore-verbosity` shows only its title by default (through `session/resume`) and can show its first and last turns; there is no `agent-shell-session-strategy` function, only `"prompt"`, `"latest"` and `"new"`; and the requests sent, which `M-p`, `M-n` and `M-r` bring back as shell-maker's do, are one history for every agent, kept by `savehist-mode` with the minibuffer's histories, where shell-maker writes a history file of its own for each kind of shell ([ADR 0061](adr/0061-agents-over-acp.md)). Picking a mode has no key of its own (`M-x agent-shell-set-session-mode`), as agent-shell's `C-c C-m` is `C-c RET`, which sends here; `C-c TAB` cycles the modes as well as agent-shell's `C-<tab>`, which `tab-bar-mode` takes. `agent-shell-header-style` `"graphical"` draws as `"text"` does, as E8 draws no icons in header lines, and the header line shows the session's model, mode and thought level; the same are in E8's own buffer-local variables `agent-shell-current-model`, `agent-shell-current-session-mode` and `agent-shell-current-thought-level`, for a mode line of one's own, where agent-shell keeps them in its internal state.
- **Batch mode** (not yet): `--batch` runs `-L`, `-l`, `-f` and `--eval`, not Emacs's other options; prompts are not read from standard input, and timers and processes run only while a script waits on them, with `sleepFor`, `sitFor` or `acceptProcessOutput`, which wait without reading input there, as in Emacs. `kill-emacs` there unwinds the code running, so `unwindProtect` cleanups and a `try`'s `finally` run on the way out, where Emacs exits without running them.

## Packages

The ports of packages Emacs does not ship, vertico, consult, magit and the rest, are repositories of their own in `e8-editor` ([features](features.md#packages-in-their-own-repositories)), and each lists where it differs from the package it follows in its README, as [e8-vundo](https://github.com/e8-editor/e8-vundo#differences-from-vundoel) does. Here are the packages E8 ships that they build on.

- **transient** (not yet): the menu cannot be searched with `C-s` and `C-r`, though the arrow keys, `M-RET` and the mouse go about it (`transient-enable-popup-navigation`), and its cursor is a hollow box, as every window's but the selected one is in E8, where Emacs's `cursor-in-non-selected-windows` `box` draws it solid; the common commands are not buttons the arrow keys reach; a menu whose first suffix is on its top line keeps the cursor on that suffix when drawn again, where transient's `transient--goto-button` misses it and goes to the next; `C-x l` asks once for a key and a level, showing each suffix's level meanwhile, rather than entering an edit mode that stays on; a prefix's man page is named in its help rather than opened, there is no `info-manual`, an infix's help does not go to its argument in the man page, and the help window is not fitted to its text; the common commands (`C-x t`) are laid out in rows rather than Emacs's three groups, without `C-g`, `C-q` and `C-z` and with `C-h`, and do not show for a moment after `C-x`; a number in `transient-show-popup`, a delay, is taken as t; and a prefix argument is not handed on to a sub-menu. Prefixes and their groups are defined with `transientDefinePrefix` and objects, not Lisp's vectors and lists.
- **org-id**: an ID made in a buffer with no file is left unrecorded (deliberate), where Emacs signals that `org-id-get` expects a file-visiting buffer, as packages' buffers with no file, org-roam's tests among them, make IDs; and `org-id-locations` is the package's own, not a variable, as E8 has no hash tables to hold it.
- **Ediff** (not yet): only the plain window layout, the control panel in a window below the buffers, as on a terminal; Emacs gives the panel a frame of its own on a graphical display. The panel's window is split off at its size, as E8 does not shrink a window below four lines. Not there yet: comparing directories, regions, windows, revisions and patches, the session registry and group sessions, `~` to swap the buffers, `z`, `i`, `E`, `G`, `R`, `M`, `=`, `m`, `s`, `/`, `v`, `V`, `<`, `>`, `h`, focusing or hiding regions by regexp (`#f`, `#h`), ignoring case (`#c`), quick help on RET or a click, the merge buffer's markers refined when combined, and the merge buffer's mode set again when it is saved. A buffer with no file saved with `wc` or `wd` is asked for one as `File to save in:`, as Emacs's save-buffer asks, rather than E8's `Write file:`. Ediff's windows, faces and fine differences are tested against an interactive Emacs, as batch Emacs, which the oracle runs, has no faces and makes the panel four lines.
