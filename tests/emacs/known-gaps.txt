# Typing | in an item narrowed with C-x n e, Emacs's M-S-<down> takes the
# accessible part of the line, "|plan", as a table and aligns it on a line of
# its own; E8's does not.

# In a buffer narrowed to one element with C-x n e, Org's element parser
# reads the whole buffer, so it still sees the item, property drawer or
# heading around the narrowing; E8's reads what is accessible. So RET in
# the item's text does not indent the new line under the item, TAB does
# not align the drawer's property, and org-copy-subtree finds no heading.

# Intentional differences, not to be fixed.
org-refile/refile-to-no-target  # the recorder answers completing-read directly, so Emacs reads a target its require-match refuses when typed; E8 refuses it with [No match], as Emacs does when it is typed.
arguments/delete-more-than-there-is  # Emacs reports an internal "Args out of range" error naming the buffer; E8 says "End of buffer". The text is unchanged in both.

# describe-current-coding-system's priority list is E8's detection order,
# which leaves out the coding systems E8 does not have: emacs-mule, the
# ISO 2022 variants and those written in CCL.

# After a command that failed (C-f at the end of the buffer), Emacs's
# undo-equiv-table no longer finds the undo on top, as the failure left an
# undo boundary, so undo-only redoes; E8's passes over the undo still.

# Passing over the only changes there are, Emacs's undo-only reaches the
# list's first position entry and moves point to it, without an error, and
# again; E8's undo history has no such entries, so the second one fails.
everyday-3/undo-only-chain  # position entries in buffer-undo-list
